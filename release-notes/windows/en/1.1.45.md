# Shroom 1.1.45

Release notes date: 2026-11-03

## Device connection

- Changed the default baud rate for 16*16 High Speed to 921600, and fixed split-packet gloves showing no data after connecting.
- Serial settings now use a numeric input. The default baud rate for the current system is shown as soon as the page opens and can be changed before connecting. Older app shells also show the default number.
- The app first connects and reads data with the default settings, and only starts detection if the current connection has had no valid data for two seconds. If it detects another compatible baud rate, it asks you to confirm before connecting.
- Normal connecting and reading messages are shown after a two-second delay, reducing message flicker during quick connections. Real errors are still shown right away.
- Improved isolation of split-packet glove data, so old data is not mixed in after reconnecting or switching systems. Serial connections cannot be changed while collecting or saving.

## Playback and usability

- Fixed re-entering a system still showing playback after returning to the system list from playback. Re-entering now shows real-time mode by default.
- Fixed abnormally short frames in 64*64 High Speed playback affecting later rendering. Clearing the screen and playback now keep the full matrix size.
- Improved the adjustment and body view layout for the Pressure Sensing Vest, unified how the full-body sensing systems are operated, and fixed the color buttons being stretched.
- When a new version is available, you can select the update notice to view details. Monitoring page resources are now preloaded while you browse the system list.
- Fixed a request race in company system catalog syncing, so a successful sync result is no longer overwritten by stale state.

## Delivery verification

- Added automated acceptance checks against the actual packaged build, covering simulated device connection, collection, saving, playback, and data export.
- Added simulated scenarios for small bed 12B, hand, split-packet gloves, and high-speed matrices. Simulated checks do not replace testing on physical hardware.
