## 数据可信度与边界

- 保存结果证明宿主存储队列及数据库提交，不证明传感器硬件零丢帧。已审计同步原生入口使用 `synchronous`，Manifest 使用 `fenced`；未知扩展保留 `untracked`，结果不能声称全保存。
- 崩溃恢复、处理超时、证据文件写入失败会明确保留未知；SQL/算法异常记部分失败。重复停止和结算不重复计数。
- 正在采集及收尾时禁止切换系统；开始新会话必须等前次收尾完成。旧异步回调不能改写下一次采集的数据库或缓存。
- 每次分析最多选择 8 条记录，扫描最多 2,000 帧及 200 万压力值；达到限制会报告部分范围。历史矩阵、标定、归零或配置不明时不从当前系统猜测。
- 分析保留来源记录、`maxId`、实际帧范围、数据阶段、参数、版本和摘要；完整压力帧留在本机，不经历史分析工具发送给模型。计算摘要及用户聊天中引用的信息仍遵从聊天/模型通道各自规则。
- 统计描述压力数据，不能在缺少标签、量纲或评价规则时宣称“舒适度准确率”、医疗结论或物理压力。
- 到期的文件导出限制针对软件提供的入口，不承诺阻止操作系统截图或用户直接读取其自己的本地文件。
- 撤回需要客户端取得签名状态才生效，不能承诺离线瞬间停机。安装状态和目录均有期限；明确 401/403 清除许可缓存，旧协议 404/405 回到签名目录，网络故障只保留未过期的签名。

## 保留期限的准确口径

聊天按服务端最后接受的完整会话快照接收时间保留 180 天，活跃会话刷新期限；不是逐条消息满 180 天裁剪。使用事件按服务端接收时间保留 90 天。

删除后保留来源与会话 ID 墓碑，旧版本或更高 revision 的快照均不会使同一会话复活。重新聊天需新会话 ID。审计及墓碑不随聊天正文清理，避免重放及失去责任记录。

定时清理需运维显式开启 `SHROOM_DATA_RETENTION_ENABLED=1`，默认不自动删除生产数据；开启后每小时每类最多 500 条。高积压应先预览，再按批次处理。单对象删除只允许启用的 `super_admin`，普通员工提交系统仍不要求新增角色。

## 发布顺序

1. 备份服务端数据库，先在测试库应用 `E:/key/drizzle/0022_upload_retention.sql`，执行清理预览和系统默认指针回填 dry-run；路径及命令以服务端专项文档为准。
2. 部署新版服务端接收端、签名安装状态及管理页，核验签名公钥一致，观察迁移、候选发布和撤回结果。清理先保持关闭。
3. 发布完整桌面安装包。本轮包含本地后端、SDK、Agent worker 及 Electron IPC，**仅更新网页不能获得全部能力**。
4. 网页发布必须沿用现有签名、宿主兼容、启动确认和回退流程；在新安装包上核对实际运行的构建 ID。
5. 通过客户设备验收后，按已确认的 180/90 天策略预览并开启清理。审计开启时间与操作者。

本轮不连接生产服务器、不运行生产迁移或清理、不上传安装包、不提交或推送 Git。

## 回退与验收

2026-10-19 本机最终验证：客户端仓库 Full **8/8**，其中后端 Electron ABI **104 个测试文件**、客户端 **861 项**、前端 SDK **533 项**，lint、两端 SDK smoke、临时生产构建与数据面性能基线均通过。服务端类型检查、临时生产构建及 **427 项测试**通过，17 项按既定条件跳过；包括独立本机 MySQL 的事务与清理测试。临时数据库已由测试流程清理，未触及生产。

- 公司系统候选不改变客户当前版本；推广、回退及撤回分别操作并审计。
- 清理尚未执行时可按部署文档回退；一旦删除并形成墓碑，不得回退到忽略墓碑的旧聊天接收端，否则客户端可能重传并重建已删除正文。
- 正常到期、凭证到期、明示拒绝、断网重启、休眠唤醒、串口断流、SQLite 写入失败、停止后的异步尾帧均需分别验收。
- 本机自动验证覆盖真实 SQLite、签名与 HTTP、独立临时 MySQL 数据库、旧指针和墓碑重放。客户端新控件另用本机合成夹具进行真实浏览器检查；不冒充客户真机或生产验证。
- 发布前仍需真实设备长时采集、安装升级/重启、生产签名配置、迁移和删除预览验收；这些需要具体部署环境与设备，不是源码测试可以替代的证据。
