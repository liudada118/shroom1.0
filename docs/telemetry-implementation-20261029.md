## 运行契约

普通前端 IPC 只能记录业务属性，不能指定事件 ID、客户范围、安装标识、旧会话或发生时间。`usageEvidence` 的宿主适配器才允许本地已提交发件箱提供原信封；公开采集状态剥离内部上下文、发件箱和范围摘要。

v1 事件仍按原白名单处理。v2 增加 `usage_delivery_summary`、`collection_outcome_reconciled` 及有限采集/质量字段。单条不超过 4 KiB，每批最多 50 条，批次不可混版。客户端先请求 `GET /api/usage/capabilities`；没有确认 v2 能力时，新增证据保留本地，v1 仍能独立发送。手动重试会重新探测能力，不重写已生成事件。

采集开始使用会话 UUID 作 `collectionId`，终态初始修订为 0；后续修订使用新事件 ID、递增修订号和前序事件 ID。`outcome` 与 `result` 的映射为 saved/success、partial或failed/failure、cancelled/cancelled、unknown/unknown。自动断线后数据完整排空可以同时是 saved 与 SERIAL_DISCONNECTED；不能把异常中断和存储失败混为一个维度。

服务端同事件同正文可重复确认；同 ID 异正文、同采集修订异 ID 均拒绝且整批回滚。乱序 2、0、1 到达时，已收到的最高修订不回退，缺前序期间标为不完整；补齐后才允许依赖完整链的统计。空记录不算非空有效使用，旧版观察时长不改名为有效展示时长。

## 容量与损失

主队列与待传发件箱按原授权范围共用最多 2000 个逻辑事件、8 MiB 已提交统计正文预算。相同 ID 的物理正文副本分别计字节；发件箱新增的修订证据及处置字段计入其 `physicalBytes`。原有压力数据库、原有采集业务证据不是新的统计副本。原子替换还需要有界的临时写入空间，不能把 8 MiB 误解为整个应用磁盘占用上限。

启动恢复存储另受最多 100 条、256 KiB、7 天、单事件 4 KiB 的更紧限制，待传部分仍进入共同预算。其本机全范围移除计数独立展示，不伪装成当前客户的质量摘要。

高频曝光、普通驻留等不能挤掉已有关键错误与终态；全部为关键记录且达到上限时，新记录仍可能被丢弃，并明确累计容量损失。主队列保留期最多 30 天，这是期限上限，不是 30 天离线无损承诺。30 秒一条摘要在没有任何其他事件时，2000 条仅约覆盖 16 小时 40 分；真实离线保障须结合事件预算、设备负载和采集数量另行验收。

错误风暴最多保留 128 类重复分区，重复增量随队列异步持久化；异常退出测试验证已完成持久化的增量可恢复。最后一次异步写入尚未完成、磁盘失败或超过容量时仍可能丢失。质量记录和证据使用同一个开关，关闭期间不补采，也不为质量监控另设隐藏上传。

每个采集日志文件读写最多 1 MiB，普通历史驻留最多 2000 份；待传发件箱、未结工作和待恢复记录独立保留并进入宿主预算处置，不能按 UUID 文件名截断。恢复仍逐文件扫描现有目录，海量历史的启动耗时没有本轮真实性能结论；超大文件保留并报告恢复缺口。快速切换授权时最多保留 16 个尚未落盘的范围快照，达到上限暂缓新增范围记录，业务继续运行。

## 发布顺序

1. 备份并在测试接收端应用 `E:/key/drizzle/0027_usage_collection_revisions.sql`，核对迁移和严格契约测试。
2. 部署支持 v2 的接收端和管理后台，核对能力接口、正确客户归属、去重、缺前序查询和统计口径。
3. 重新构建并验证桌面安装包，执行实际 IPC、断网补传、主动诊断导出及真实设备采集。
4. 按规范填写真实场景任务、负责人、验收阈值和复查日期后，再做客户试点。
