# Shroom 内置 Agent 使用指南

> 更新日期：2026-10-16。本文说明当前实现与验证范围，后续能力仍需逐项接入。

Shroom Agent 提供软件内对话入口，能够查询设备与系统、生成展示配置提案，并在用户点击后应用支持的更改。配置保存、设备连接、收到实时数据和真实画面正确，是不同的验收结果。

## 1. 第一次使用

1. 打开 Shroom 桌面软件，点击右下角 **Agent**。
2. 点击 **模型设置**，选择模型服务商及模型，填写对应的 API 密钥。
3. 保存后先发送：“当前有哪些展示系统，设备是什么状态？”
4. 查看回答与执行记录；涉及修改时，先查看提案内容，再点击应用。

按 Enter 发送，Shift + Enter 换行。中文输入法选词时 Enter 不会提交任务。关闭抽屉只隐藏界面；要结束执行，请点击 **停止任务**。

普通浏览器开发页面没有桌面桥时，会显示“在桌面软件中使用 Agent”，不会模拟设备连接或执行结果。

### 默认简洁回复

软件已内置简洁表达规则，无需安装额外 Skill 或在每次聊天中重复设置。新会话、历史续聊及工具后续轮次都携带同一规则：先说结论，普通回答优先 3–6 行；必要操作通常不超过 5 步，过程查看本轮任务卡与执行记录。失败保留关键原因及一个可行处理动作，不在正文罗列全部内部标识或反复复述状态。

需要更多信息时，直接发送“详细解释”“展开说明”或要求完整代码、文档和清单。默认篇幅是模型表达指引，软件不会按行截断正文，也不压缩线序、协议、算法源码或工具参数；实际校验、权限、失败记录和待验证状态仍完整保留。不同模型遵循程度可能不同。规则属于内置 Agent 运行时，开发环境重启 Agent 进程后生效，客户安装版需随包含此改动的软件更新交付。

### 客户安装、升级与聊天同步

客户首次填写自己的 API Key。同一电脑、同一系统账号和相同应用数据目录下，升级保留 Key、聊天及安装版采集记录；更换电脑或账号需重新填写 Key。开发版和安装版 Agent 可能共用 `userData/agent`，本机安装后看到旧聊天不代表聊天被装进安装包。打包现在生成空采集库模板，排除本机 Agent 数据及原生副本目录。

模型设置下方的 **聊天同步** 首次使用默认自动开启，自动复用本机软件密钥，不需要额外填写地址或凭证、保存同步设置。地址和凭证等配置折叠到“高级同步设置”，已有手动关闭或自定义接口选择保留。同步当前会话、之后的聊天及打开的旧会话，上传正文、任务状态与附件名称，不上传原附件或采集数据库；正文中的采集摘要仍会上传。

默认上传地址为 `https://shroom.jq-industries.com/api/agent/conversations`。服务器只允许已登记的有效软件密钥上传，并自动显示绑定公司；未绑定公司的在线密钥按密钥独立归类。离线 RSA 密钥需有效客户关联并通过签名验证，按 `offline_key_id` 独立留档；服务端需执行 `0021_agent_chat_offline_sources` 迁移。已有独立凭证可清除后保存，改用软件密钥。自定义接口仍需独立上传凭证，不自动发送软件密钥，也不会使用模型 API Key。

面板显示待同步数量、成功时间及错误，断网自动重试；关闭停止后续发送，保留本地记录和队列。服务器未就绪或密钥被拒时，聊天仍保存在本机，面板报告失败，不声称已同步。上传凭证与模型 Key 分开加密保存，不能互相代用。聊天同步包含正文，与只上传有限事件的使用统计开关独立。服务端契约、容量和联调步骤见 [聊天同步接口文档](agent-chat-sync-api.md)。

### 模型连接怎么填

| 字段 | 填写方式 |
| --- | --- |
| 模型服务商 | 选择 **DeepSeek 官方 API**、**OpenAI 官方 API** 或 **自定义地址／中转站**。官方选项自动设置地址；自定义选项可填写原中转地址。 |
| 服务地址 | DeepSeek 官方为 `https://api.deepseek.com`，OpenAI 官方为 `https://api.openai.com/v1`；自定义服务填写其 API 基础地址，不要追加 `/responses`。 |
| 模型名称 | DeepSeek 官方可选 `deepseek-flash`、`deepseek-v4-pro`；其他服务按对应预设或手动填写模型 ID。RelaxyCode Codex 组仍包含 `gpt-6-astra`、`gpt-5.6-sol`、`gpt-5.6-terra`、`gpt-5.5`、`gpt-5.5-openai-compact`。实际可用性由当前密钥及账户权限决定。 |
| API 密钥 | 填写所选服务商自己的密钥。切换服务地址时必须填写新密钥；同一地址切换模型可留空保留已有密钥。 |

DeepSeek Flash 支持图片输入；V4 Pro 官方暂不支持视觉输入。选择 V4 Pro 发送图片时，软件会在请求前提示切换到 Flash，不会把图片任务提交给 V4 Pro。[官方模型能力表](https://api-docs.deepseek.com/quick_start/pricing/)

当前接入的是 Responses API。DeepSeek 官方的 [Responses API](https://api-docs.deepseek.com/guides/responses_api/) 支持本软件使用的流式输出和函数工具调用；DeepSeek 模型清单见[官方模型文档](https://api-docs.deepseek.com/quick_start/pricing/)。仅支持 Chat Completions 的服务不能直接使用；第三方兼容服务仍需实际验证。OpenAI 接口说明见 [Responses 官方指南](https://developers.openai.com/api/docs/guides/migrate-to-responses)、[工具调用指南](https://developers.openai.com/api/docs/guides/function-calling)和[流式响应指南](https://developers.openai.com/api/docs/guides/streaming-responses/)。

下拉框是常用模型预设，不会读取账户的模型清单。预设接口能力核对于 2026-09-17：[GPT-5 mini](https://developers.openai.com/api/docs/models/gpt-5-mini)、[GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini)、[GPT-5.4](https://developers.openai.com/api/docs/models/gpt-5.4)、[GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini)。手动填写的模型也需要支持 Responses API 和工具调用。

远程地址必须使用 HTTPS；`localhost`、`127.0.0.1` 和 `[::1]` 的本机服务允许 HTTP。地址不能包含账号密码、查询参数或片段。**更换服务地址会清除旧服务密钥，需要重新填写。**

DeepSeek 官方直连只改变模型请求目的地；若已开启“聊天同步”，聊天仍按同步设置上传到你配置的服务器。软件不代替用户注册 DeepSeek 账户或获取官方 API 密钥。

密钥由 Electron `safeStorage` 加密后保存在本机，界面只接收“是否已配置”。操作系统安全存储不可用时会拒绝保存；换电脑、换系统账号或解密失败后，需要重新填写。

### 无法连接模型服务

桌面 Agent 的模型请求使用 Electron Chromium 网络栈，自动读取系统代理设置；本机设备接口保持直连。需要代理才能访问模型服务时，请先启动代理并启用系统代理，无需把模型服务地址改成代理端口。网络行为见 [Electron net 文档](https://www.electronjs.org/docs/latest/api/net)。

2026-09-17 修复了原 Node `fetch` 绕过系统代理导致的连接超时。更新后需要**完整退出并重启 Shroom**，仅刷新页面不能替换已运行的 Agent 进程。

错误提示现在区分代理不可用、地址解析失败、安全证书失败和连接超时；证书失败时检查系统时间及代理证书，不关闭证书验证。服务返回 401 时再检查密钥，429 时检查额度或请求频率。网络连通不等于密钥、模型权限或余额已验证。

### 模型响应超时

旧版对每轮模型请求设 90 秒的固定截止，模型即使持续流式返回数据也会被切断，整个 Agent 任务另有 4 分钟上限。现在改为模型服务连续 4 分钟没有返回任何数据才中止该轮，收到响应头或新的响应数据后重新计时；整轮任务上限为 15 分钟，仍可随时点击停止。中转站或模型服务主动断开、自己的超时设置与软件超时是不同问题，软件无法延长服务端的限制。更新安装包后须完整退出并重启 Shroom，已失败的任务不会自动重试。

### HTTP 403 与模型分组权限

出现“当前 API 密钥所属分组未获授权使用所选模型”时，请到服务商控制台查看该密钥绑定的分组，以及分组允许使用的模型。在 Agent 模型设置中选择可用模型，或填写具有所需权限的密钥；服务地址必须与密钥所属服务一致。

2026-09-21 现场最小请求中，配置的第三方服务对 `gpt-4.1-mini` 返回 HTTP 403，SSE 错误事件明确说明“当前分组未授权使用该模型”。这表示当前请求被分组权限拒绝，不代表模型对所有账户不可用。软件无法替账户开通模型权限，也不会自动更换模型或密钥。

同一天使用相同服务地址和密钥，`gpt-6-astra` 最小流式请求及项目 provider 请求均返回完整结果 `OK`。可重启软件后，在模型设置中选择 **Codex（RelaxyCode）→ ChatGPT-6-Astra** 并保存，再发起新任务。此验证仅覆盖短文本模型连接，未验证真实工具任务；其余四个模型由用户提供清单，未逐个实测。服务商清单见 [RelaxyCode 模型价格](https://www.relaxycode.com/pricing)。

错误解析同时支持 JSON 与 SSE，仍限制为 16 KiB 并只输出固定提示。其他未识别的 403 提示检查密钥分组、模型调用权限和服务商访问限制。修复后需完整退出并重启 Shroom，再发送新任务；旧执行记录保留原提示。

### HTTP 404 与组织验证

OpenAI 可能在组织未验证时返回 `404 / model_not_found`，即使同一密钥可以查询模型清单。2026-09-17 现场的 `gpt-5-mini` 请求就是这种情况，服务端明确要求先完成组织验证。

出现“当前 API 组织尚未完成验证”时，登录该密钥所属账户，在 [组织设置](https://platform.openai.com/settings/organization/general) 点击 **Verify Organization**；服务端提示完成后权限可能需要最多 15 分钟生效。软件无法代替账户持有人完成验证。

需要先使用 Agent 时，可在模型下拉框中选择其他已获授权模型。该次现场测试中 `gpt-4.1-mini` 的最小流式回答成功，因此加入了下拉预设；其他账户仍须以实际调用结果为准。软件不会自动替换已保存模型。

组织验证、模型不存在/项目无权限及普通接口 404 现在分别提示。错误解析最多读取 16 KiB，只匹配已知原因后输出固定文字；不把服务端原始正文、密钥或链接显示给用户。

### 能否复用 CC Switch 的配置

Shroom 不会自动读取 CC Switch 当前选中的供应商。能否复用地址和密钥，取决于该供应商的接口、模型权限和外接要求。

- 供应商支持 **Responses API**：Shroom 填对应的 API 基础地址（通常以 `/v1` 结尾）、实际模型 ID 和允许调用该模型的密钥；不追加 `/responses`。
- 只有 **Anthropic Messages** 的 Claude 配置：当前版本不能直连，需要补 Anthropic 适配或使用提供 Responses 接口的兼容路由。不能仅换模型名称。
- 服务商额外要求自定义请求头或指定令牌分组：仅填写现有三个字段可能仍不能使用，需按服务商规则补接入配置。

[CC Switch 项目指南](https://github.com/farion1231/cc-switch/blob/main/docs/guides/codex-claude-routing-guide-zh.md)说明 3.17.0 起可将 Responses 请求路由至 Anthropic 上游；具体代理配置不能照搬为 Shroom 已验证支持。米醋用户还应核对其[外接协议、令牌分组及请求头要求](https://docs.micuapi.ai/external-compat)。

“该页面无权操作 Agent”属于桌面页面权限校验失败，发生在发送模型请求之前；更换 API 密钥不能解决这个错误。
2026-09-15 已修复开发服务器使用动态端口时的误拒绝。更新代码后需要完全退出并重新启动 Shroom，让 Electron 主进程加载修复；仅刷新网页不能更新主进程。

### GPT 的密钥与费用由谁提供

如果“识别本轮当前系统”已完成，随后出现 **HTTP 402**，表示本机系统读取完成，但后续模型请求被服务商拒绝，整轮任务仍为失败。请在所配置服务商后台检查账户余额、当前 Key 的剩余额度、套餐限制和该请求的日志。软件现在对 402 给出独立提示，不再笼统要求修改模型名称；也不会自动换 Key、换模型或重复请求。402 的具体业务含义由服务商决定，仅凭状态不能确认欠费；[HTTP 标准](https://www.rfc-editor.org/rfc/rfc9110.html#name-402-payment-required)仍将它保留待用。

当前版本由使用者在模型设置中填写自己的 API Key，费用归该密钥所属的服务账户。官方 OpenAI Key 对应 `https://api.openai.com/v1`；第三方 Key 必须配该服务的地址和允许的模型，不能混用。密钥直接填在软件里，不需要发到聊天中。

官方 API 按实际用量计费，ChatGPT 会员与 API 账单独立；最新费率见 [OpenAI API 价格](https://developers.openai.com/api/docs/pricing)，账号设置见 [官方快速开始](https://developers.openai.com/api/docs/quickstart)。第三方服务的实际单价、套餐和可用分组以该账户后台为准，不能套用 OpenAI 官网价格。

一个 Agent 任务可能包含多轮模型请求。消息、附件、工具定义和工具返回的摘要会进入输入用量，模型回复及计费推理进入输出用量；预算应累计所有轮次。串口观察与本机配置操作本身不调用额外的 OpenAI 托管工具，但相关信息再次发给模型时仍属于输入。

当前没有软件内充值、用户额度分配或金额硬上限。将来若由软件提供方统一付费，应另建服务端密钥、用户身份、额度和用量记录模块，再由桌面端访问该服务；不要把所有客户共享的密钥写进安装包。

## 2. 当前可以做什么

| 能力 | 例子 | 当前边界 |
| --- | --- | --- |
| 查询软件状态 | “列出系统、通道和可用串口。” | 从本机接口读取真实状态。 |
| 查询能力目录 | “有哪些协议、算法包和显示选项？” | 使用本机注册目录，不猜测不存在的标识。 |
| 创建展示系统 | “创建一个单传感器矩阵系统，沿用 hand 的图表和工具布局。” | 创建独立矩阵系统并复用监测工作区布局；协议、矩阵、线序、点位和 2D/3D 渲染器按新系统配置。创建不会自动激活或连接设备。 |
| 复制已有系统 | “把系统 X 完整复制为新系统 Y。” | 读取真实 Manifest 后生成提案，复制配置、映射和资源文件，使用独立系统身份；只有内置页面但没有 Manifest 的目标不能通过此工具复制。 |
| 修改展示 | “给这个自定义系统添加最大压力统计，并调整配色。” | 支持可写系统的配色、叠加层及内置统计图表。 |
| 连接指定设备 | “将这个系统的指定传感器连接到已列出的 COM 口。” | 先生成连接提案，用户点击后才切换系统或连接。 |
| 检查传感器数据 | “检查这个通道有没有收到有效实时帧。” | 有界观察通道并返回点数、数据来源、数值摘要及质量信息。 |
| 训练分类算法 | “用已采集的抚摸和拍打数据训练识别算法，测试后保存。” | 缺少有效选区时在本轮显示选数卡，勾选后自动继续并复用采集标签；默认本机 CPU 比较内置分类器，用户指定规则时仍支持受限 Python。保存后仍需绑定才启用实时识别。 |

创建时可使用无算法处理、受限 JSON 数值处理，或目录中可附加且兼容的可信算法包。需要外部资源文件、多传感器融合绑定等额外条件的算法包不在当前自动创建范围内。

内置统计图表支持总压力、平均压力、最大压力、受压点数和受压面积。已有系统的渲染器/profile、协议和点位映射不能通过“修改展示”工具切换。

### 复制系统与传感器参数错误

`prepare_create_system` 用于从零创建，需要 1～8 路完整传感器定义。`arguments.sensors: invalid array length` 表示模型提交的 sensors 不是有效数组或数量不符，旧版本没有说明缺失项。新版错误会明确说明实际数量，并提示复制已有系统时改用 `prepare_duplicate_system`。

复制工具只需要源系统 ID、新 ID、名称和摘要，可选修改已有显示段。旧版配置的 `sensor`、新版的 `sensors[]` 都可保留原结构，模型无需重新抄写大数组。点击应用时，后端会检查源配置及映射/算法定义是否变化；变化后需要重新生成提案。副本会获得独立的传感器类型，避免被系统列表按原类型合并。更新后需要完整退出并重启 Shroom。

复制保留原系统的功能，不能产生原来没有的呼吸数据。呼吸率、呼吸波形和压力曲线是不同数据；当前 Agent 图表工具只支持上述五种压力/面积指标。缺少兼容算法或图表接入时，应说明具体缺口，不能把压力图表改名为“呼吸”。复制前也需要核对源系统的名称和渲染器，矩阵页面不能当作同名的三维监测页面。

工具失败后，模型会收到错误并可修正参数继续；尚未恢复的失败不会仅因模型结束回复而显示“已完成”。此前失败记录保留；同类操作重试或改用复制工具成功后，可以正常进入“等待应用”。

### 连接提案的条件

连接提案必须明确 `systemId`、`sensorId` 和当前枚举出的 `portPath`，不能猜测 COM 口。准备及应用时会检查目标、授权、配置版本和当前运行状态。

建议先在软件中进入目标展示，再让 Agent 连接指定端口。Agent 可以切换后台目标；已打开的监测画面沿用现有状态广播同步，首页选择器不会因连接成功自动进入展示。连接后再从首页执行一次“进入系统”可能触发原有切换逻辑并关闭端口，此时需要重新连接。

以下情况会拒绝连接：正在采集或回放、串口已打开或正在重连、目标端口不可用、授权无效或过期、配置或当前目标发生变化。Agent 不会为了完成任务自动关闭原有连接。特殊 legacy `minzhen` 以及 `seat` / `sensor` 角色暂不支持这条自动连接路径。

连接后会观察匹配目标通道的有效 `realtime` 帧。串口显示 `open` 或连接请求被接受，不等于已经收到有效数据；只有回放帧、空帧、点数不符、矩阵行列不符/缺失或过期数据，都不能当作实时设备验证通过。观察到实时帧也不代表前端画面、物理线序和标定已经正确。

### 暂未支持

- 根据新协议生成任意驱动代码、执行任意命令或安装模型生成的可执行代码。
- 任意自定义图表、执行任意 Python 或安装第三方训练框架；切换现有系统的渲染器配置。内置 CPU 分类训练和受限规则算法见第 8 节。
- 自动开始采集、定时采集、批量导出或分析报告。
- PDF、图片 OCR、音视频理解。
- 在界面中切换已归档的旧会话；自动恢复创建系统或设备连接操作。

## 3. 添加图片、协议与点位附件

点击 **添加附件** 选择文件，或在聊天输入框中按 **Ctrl+V** 粘贴截图、图片和文件。Windows 资源管理器中复制的文件也可直接粘贴；普通文字仍插入输入框。附件先进入待发送列表，图片有缩略图，可在发送前移除。导入失败会提示原因，并保留已有输入和附件。

提交任务后，所选文档的解析文本和图片原始内容会发送到配置的模型服务；图片使用 Responses `input_image`，需要该服务和模型支持图片输入。粘贴成功只代表附件已导入，不代表模型已读图。

| 限制 | 当前值 |
| --- | --- |
| 格式 | PNG、JPG/JPEG、WebP、GIF 图片；TXT、Markdown、JSON、CSV、TSV、LOG、XLSX 文件 |
| 文本编码 | UTF-8；JSON 还会检查语法 |
| 单文件 | 非空，最多 8 MiB，解析文本最多 120,000 个字符 |
| 一次导入/任务所选附件 | 最多 6 个 |
| 一个会话保留附件 | 最多 12 个，合计解析文本最多 240,000 个字符 |
| 单次任务附件文本总量 | 最多 120,000 个字符 |
| XLSX | 最多 8 个工作表、合计 12,000 个单元格；另有限制压缩结构及展开大小 |
| 图片 | 主进程解码校验，最多 2500 万像素，聊天界面显示缩略图 |

XLSX 保留工作表名、单元格地址和文件中的缓存值；不执行公式、宏或外部连接，也不会重新计算或格式化日期。公式没有缓存值、存在公式错误、单元格地址重复或内容超限时，会拒绝导入。可先在 Excel 中重新计算并保存，或导出 UTF-8 CSV。

附件不会被静默截断后继续用作线序。任务发送后会清空“待发送附件”选择；后续任务仍需要原始资料时，请重新添加相关附件。过大的资料可拆分，并新建会话处理。

## 4. 如何理解任务与提案

| 界面状态 | 含义与下一步 |
| --- | --- |
| 执行中 | 模型正在回答或调用允许的工具。 |
| 正在核验 | 正在应用、恢复或检查实际结果。 |
| 等待应用 | 已生成提案，尚未执行对应更改。 |
| 已完成 | 本次任务结束；设备是否有有效数据仍要看具体核验结果。 |
| 执行失败 | 查看错误与步骤记录；不要把之前的部分结果当作整项成功。 |
| 已停止 / 已中断 | 后续调度已停止，或软件/Agent 进程曾中断。 |
| 需要检查结果 | 写入或连接已发出，但没有完整确认；先检查当前系统状态。 |

模型只准备提案。提案卡片提供摘要、修改后配置，以及适用时的修改前配置；点击 **应用此方案** 后才会创建/复制系统、写入配置或连接设备。应用前会重新核对版本及能力，防止覆盖用户在其他界面进行的修改。

**恢复此项更改** 仅针对已应用的展示修改，而且当前系统版本必须仍等于该提案写入的版本。创建或复制的新系统会保留；设备连接不提供自动回退。发生不确定结果时，不自动重试或撤销，以免重复操作。

同一时间只执行一个任务或变更。停止任务不会撤销已经完成的操作。重启后会恢复当前会话记录，将未完成任务标为中断，将写入期间中断的提案标为不确定，不自动接着执行。

点击 **新会话** 会将当前消息、任务和附件归档，然后打开空会话。会话不再按任务次数强制结束；单条会话记录超过本地保存大小保护时，仍会提示新建会话。

点击面板顶部的 **历史会话**（时钟图标），按最近活动查看会话，可搜索首条消息标题。点击记录可恢复消息、执行记录和附件预览并继续聊天；当前会话会自动保存。运行任务或导入附件期间不能切换。单个损坏的归档不阻止其他记录显示，打开失败时保留当前会话。完整退出并重新启动软件后，新入口才会使用更新后的主进程。

## 5. 数据保存与隐私

数据目录由 Electron `app.getPath('userData')` 决定，其下使用独立的 `agent` 子目录。Windows 通常位于 `%APPDATA%` 下的应用目录；实际目录以运行实例的 `userData` 为准。

```text
<userData>/agent/
├─ settings.json                 服务地址、模型名和加密后的 API 密钥
├─ state.json                    当前会话、任务、提案、已解析附件
├─ conversations/<会话ID>.json    新会话与切换产生的历史归档
└─ attachments/<附件ID>.image     图片原始字节，独立于 JSON 状态保存
```

- 只有 API 密钥使用系统加密。**消息、配置提案、附件解析文本和图片均未加密保存在本机**，不属于加密保险箱。
- 设置密钥不写入浏览器存储、不回传到聊天界面；主进程将解密后的密钥交给独立 Agent 进程用于模型请求。
- 发出的模型请求包含本次消息、有限的近期聊天历史、所选附件文本和图片，以及工具调用返回的软件状态或数据摘要。实时检查可能包含少量传感器样本；不会把整个高频数据流持续交给模型。
- 模型请求使用 `store: false`；所选模型服务的实际数据处理和保存规则仍由该服务决定。
- 当前支持历史列表、搜索和继续聊天，尚无会话删除入口。备份时保留整个 Agent 目录及图片文件；不要在 Agent 运行中直接修改记录文件。

## 以内置系统为模板创建

支持目录中的全部 28 个内置系统，包括手部检测、各类手套、机器人、足底、床垫、座椅等。

- 手动：打开“展示系统配置器” → “以内置系统为模板创建” → 选择原系统，填写新名称和独立 ID → “创建系统” → “进入系统”。保存和进入分别反馈；进入失败时，已保存的系统仍可从目录找到，不需要重复创建。
- Agent：例如“以内置手部检测 hand 为模板，新建一个名为手部观察、ID 为 hand-observation 的系统，保留协议、线序和展示。”检查方案后点击“应用此方案”，再从系统列表进入。

“沿用 hand 的图表和工具”指复用监测工作区布局，不复制 hand 的固定设备输入。Agent 对新矩阵系统使用 `prepare_create_system`：创建时就生成与 hand 同顺序的面积、压力和可扩展图表侧栏，工具仍在工作区；原始协议点数、映射后的矩阵尺寸、线序和 2D/3D 渲染方式由新系统独立定义。单传感器矩阵默认显示 3D 点图，中间可按需切换渲染器；图表和工具区不随之切换。没有单点物理面积标定时，覆盖范围按“格”统计，不冒充物理面积。

例如 1024 点原始帧抽取并重排为 23×23：若用户给出 `arrToRealLine(arr, arrX, arrY, 32)` 一类函数，Agent 只需提交 `axisMapping` 的原始列数及 x/y 坐标段，软件按 y 外层、x 内层计算 529 个 1 基线序索引和行优先展示点位。传入的显式数组与坐标规则冲突、范围越界、数量不足或坐标重复都会在生成提案前拦截；提案显示首行、换行、末尾索引供核对，应用后逐项读回线序和点位。物理方向仍须用真实设备帧确认。侧栏统计使用映射后的矩阵通道，不取渲染插值结果。若提供真实点位坐标，还可设置 `coordinateMap` 改变 3D 点阵的物理形状；没有坐标时显示规则矩阵，不凭空推断形状。只有明确要求连同专用原生画布和设备定义完整复制时，才使用 `prepare_builtin_system`；这种原生副本沿用来源系统的固定矩阵、协议与线序。任意自定义三维模型文件仍需作为系统资源提供，不能靠选择 hand 模板凭空生成。

副本沿用原生页面、串口处理和设备控件，有独立的名称、算法和图表配置、画布/公式图表偏好、归零与采集目录。修改副本不影响原系统和其他副本。运行权限仍取决于原系统的授权；创建副本不会增加授权范围。原生实现随软件升级；当前编辑器支持下列配置项，不提供专用协议和渲染器源码编辑。

在配置器列表点击已创建的系统即可打开“编辑系统”；创建成功后也可立即点击“编辑系统”。已经创建的旧副本会自动读取默认配置，无需重建。

| 可修改项目 | 操作 |
| :--- | :--- |
| 系统名称 | 修改名称后保存 |
| 原有图表 | 分别显示或隐藏压力、面积图表 |
| 算法 | 添加目录中的兼容算法，选择输入通道，启用、停用或删除；删除算法同时删除其绑定图表 |
| 算法图表 | 添加、删除，修改名称、输出指标、颜色、小数位；只删除图表会保留算法 |
| 系统 | 删除前切换到其他系统；仅移除系统配置，保留采集文件，旧 ID 不再复用 |

例如添加呼吸率：编辑系统 → 添加兼容的“床垫生命体征”算法 → 添加算法图表 → 选择“呼吸率”输出，填写“呼吸率趋势” → 保存更改 → 进入系统。可离线保存，收到兼容实时数据后才运行算法并绘制真实输出；没有结果、算法异常或输入不兼容时显示相应状态。输入尺寸匹配不等于已验证实际传感器的呼吸测量效果。

也可对 Agent 说“给当前系统添加呼吸算法和呼吸率趋势，保留原有展示和图表”，或“删除当前系统的呼吸率图表，保留算法”。Agent 自动识别当前系统，通过 `read_system` 与实际目录构造独立配置提案；应用前不写盘，应用后读取验证，可在未被其他操作改动的情况下恢复更新前配置。删除系统需明确提出并应用删除方案。

当前算法图表显示实时标量的连续趋势，算法输出尚未接入采集文件、回放或 CSV；原有压力采集和回放保持原生能力。原生副本的串口连接仍使用页面设备控件。

每轮 Agent 回复现在紧挨本轮执行记录；旧任务记录折叠后仍在原轮次，不再统一排到全部回答之后。

## Agent 识别当前系统

进入系统后可以直接问“当前是什么系统？”或“以当前系统为模板创建一个副本”。每轮任务开始时，Agent 自动读取软件实际选中的系统，并在执行记录的“识别本轮当前系统”步骤显示名称和 ID。

识别范围包括内置目录中的全部系统、原生模板副本和自定义 Manifest 系统。副本保留自己的名称和 ID，同时提供原生来源，避免将副本当成原系统。切换系统后，新任务会重新读取；未选择、未知系统或查询失败时明确报告状态，不从旧对话猜测。

本轮记录是任务开始时的快照，不是持续更新的页面标签。识别目标不代表已验证串口数据，也不代表 Agent 可以修改该系统的所有功能。更新后需完全退出并重启 Shroom，以加载后端和 Agent 新能力。

## 8. 用采集数据编写分类算法并实时接入

完全退出并重启包含本功能的 Shroom 后进入目标系统，直接告诉 Agent 要分析或开发的算法，例如“用我采集的拍打和抚摸数据生成识别算法”。没有可用的数据选择时，Agent 可在本轮对话中显示 **算法数据选择** 卡片，不需要先找到工具栏入口。

1. 勾选 2～8 条采集记录即可，自动沿用采集名称中的标签，例如 `达_拍打_日期 时间戳` 带入“拍打”，无需重复填写。可以按当前页的采集标签筛选并批量勾选；至少提供两类开发数据。
2. 需要自行打标签时，展开单条记录的 **修改标签或读取范围（可选）**；也可展开 **批量修改标签（可选）**，填写统一类别并应用到当前筛选内已勾选的记录。读取范围默认每条前 256 帧，每条最多 2000 帧，总计最多 200 万个压力数值，识别窗口默认 32 帧。
3. 有另外采集的同类别记录时，将其用途设为 **独立验证**。同次采集的不同通道不能分到开发与验证两组；只有两条记录时可以先开发，但结果不能作为独立验证准确率。
4. 在对话卡片点击 **使用所选数据并继续**，软件核验范围后自动继续本轮任务，无需再发“继续”。默认调用 `train_algorithm`，在本机单线程比较逻辑回归、决策树和 32 棵树随机森林，选取有真实报告的候选并生成保存提案。训练最长 60 秒，可以停止；不需要显卡、CUDA 或另行安装训练库。仍可使用输入框旁的 **算法数据** 手动准备选区。
5. 查看提案的模型类型、特征、评价方式、窗口正确率和错分示例；用户明确要求手写规则时才查看受限源码。点击 **应用此方案** 后保存模型或源码与报告，具有输入契约的版本同时登记到当前系统实时算法目录。保存不等于实时启用；新增模型也能随公司系统包交付，无需为每个模型重新打包整个软件。
6. 需要实时运行时，对 Agent 说“把已保存的拍打／抚摸算法接入当前系统，添加动作识别图表，保留已有配置”。Agent 查询真实包 ID 后，按当前系统类型生成原生独立或用户 Manifest 的算法与 `classIndex` 图表绑定提案，不另建系统。应用后在兼容实时帧到达时开始积累窗口并分类。串口未连接时可先添加为停用，连接设备后让 Agent 启用并核验采样节奏；保存、绑定和观察到有效分类是三个不同状态。

用户 Manifest 的算法绑定保存在同一用户数据目录的 `manifest-algorithm-bindings`，随升级保留。它只引用已保存算法包、传感器通道和声明的数值指标；修改绑定不会改写原系统的协议、线序、展示矩阵及历史采集。系统输入或映射后来发生变化时会暂停旧绑定并要求重新核对。

对话中的数据请求只展示当前系统的采集目录及标签，用户确认前不授权读取压力帧。等待选择时不持续调用模型；选择卡可取消，目录加载或选择校验失败时保留输入供重试。切换系统后需先回到请求对应系统或发起新的任务，不能把另一系统的记录交给原任务；已处理的历史卡片不能再次提交。等待中的请求随本机会话保存，重新打开会话后仍需用户明确确认。此交互使用新增桌面 IPC，客户需更新完整软件，不能只靠网页更新启用。

旧采集名称由“采集名称、特征标签 1、特征标签 2”中的非空项用下划线连接，没有单独的标签字段。自动带入只识别软件生成的日期/时间戳后缀，默认取末尾标签，保留“平躺_2”这样的名称与数字组合；不从压力值或任意文件名猜动作。若标签自身含下划线，可在批量编辑中统一选择“去掉名称开头第一段”或“完整采集名称”。无法提取时显示缺失，可手动补填；不会静默截断超长标签。手动改过和已保存的类别不随提取规则改变，刷新保留当前输入。

批量操作只作用于当前页和当前筛选内的记录，切换标签筛选保留其他已选记录，超过每批 8 条时明确显示实际勾选数及未选数。翻页仍清空本页选择；保存后的类别与范围属于该会话的算法数据选择，不改写采集库。分类开发所需的两类数据、独立验证隔离和数据总量限制仍由后端校验。

默认训练只使用用户已选范围，不会自动扩大为整条采集记录或扫描其他数据。特征按数据、窗口、矩阵、版本和目标采样间隔在本机缓存；同一输入可复用特征。候选选择在独立采集组足够时使用按采集分组的交叉验证，同次采集不会拆进不同折；组数不足时明确标为仅开发集结果。用户提供的独立验证记录只在候选选择并冻结后评价，不用于调参或拟合；评价尝试写入持久使用台账。

CPU 模型使用 `cpu-classifier-v1` 纯 JSON 保存线性系数或树，禁止 pickle 和任意可执行代码。最多 64 个模型特征、8 类、32 棵树，每树最多 511 节点，模型最多 2 MiB；非法索引、循环、共享子树和非有限数值会拒绝。最高类别概率低于宿主固定阈值 0.55 时输出“未知”，该概率不等于实际识别准确率。安装版使用随软件交付的固定训练组件，缺失时需更新完整软件，不要求客户自己安装依赖。

用户明确需要自行制定规则时，仍可使用 `def predict(f):`，返回开发集类别列表的 0 基下标，无法判断返回 `-1`。支持局部数值变量、四空格缩进、`if/elif/else`、算术与比较、`and/or/not`、`abs/min/max/sqrt`。不支持循环、导入库、网络、文件、进程或硬件访问；由专用数值 AST 解释器执行，不交给 `eval`、Node `vm` 或主 Python worker，也不因此开放完整 Python 权限。

输入 `f` 提供窗口特征：持续秒数、帧数、压力点数、帧总值均值/标准差/最小值/最大值、最大上升/下降速率、相邻帧总值绝对差均值、正值点数均值和单点峰值。压力保持采集存储值的原单位，速率按秒计算；不把已处理的存储数据宣称为未处理的原始协议字节。

自动训练的 `pressure-spatial-v2` 保留这 12 项全局特征；只有宿主提供且验证 `rows × cols = total = 点数` 的映射后展示矩阵时，才追加 `copX/copY`、左右/上下压力占比、左右对称度和 X/Y 扩散度，共 21 项。位置按展示矩阵行优先顺序，使用归一化坐标；没有可靠矩阵只用 12 项，不猜设备形状。实时执行复用同一特征函数，树输入按 float32、线性模型按双精度计算，与本地训练评价保持一致。

限制与报告规则：

- 当前系统及明确选中记录才可读取，不支持任意 SQL 或路径。分析不会切换回放、停止串口或修改采集库；记录增长、系统切换时需重新选取。
- 统一特征计算最长 10 秒，线程老生代内存上限 128 MiB；CPU 训练独立子进程最长 60 秒，取消、超时或输出超限会终止，不影响串口采集。仅受限源码测试每任务最多 6 次，源码最多 16000 字符、200 行，单窗口最多 4000 个解释步骤。
- 不混用不同压力点数或不同存储阶段。同毫秒重复采样在分析时跳过并报告数量，倒序或超过 5 秒的间断拒绝分析。窗口不重叠，尾部不足一个窗口的帧不参与评分，其数量写入报告。
- 开发集有界摘要、模型摘要和评价结果交给模型服务；完整压力帧和逐窗训练特征留在本机。独立验证数值不参与生成前的特征摘要。
- 独立验证按采集记录隔离，需要覆盖开发集全部类别。记录使用台账持久化，已经用于验证的同次采集不能在改代码后再次声称未见验证；失败或取消的验证尝试也保留使用标记。
- 正确率按窗口统计，报告区分分组交叉验证、仅开发集测试与独立记录验证，同时列出采集记录、范围、混淆矩阵、未知结果、预测明细及数据和模型/源码摘要。开发集通过不证明新采集上的可靠性；独立验证结果也仅代表所选记录。
- 应用保存新版本，不覆盖旧版本。保存与实时启用分开，绑定并启用后才实时分类。历史播放同步识别、任意外部模型训练和第三方依赖安装尚未接入；自动训练仅限软件内置的三个 CPU 候选。

新增本地存储位于 `<userData>/agent/algorithm-lab/`：`drafts/` 保存已测试模型或源码与完整报告，`installed/` 保存已应用版本，`validation-ledger.json` 保存验证数据使用记录。模型、源码和报告按普通本地 JSON 保存，系统包可携带已绑定模型及报告，不附带训练环境或客户采集库。

实时接入规则：

- 保存的输入契约包括压力点数、存储字段阶段、窗口帧数和平均采样间隔；CPU 模型另外把特征版本、矩阵与模型摘要绑定到报告。同点数但不同行列也不能用于空间模型，启用前与运行时都会复查。实时使用对应阶段与同一特征函数，不用归一化值替代已测试的处理值；按目标时间选择最近真实帧，不插值或补帧。窗口节奏超出目标的 0.5～1.5 倍或跨越过大缺口时暂停识别，数据恢复后重新积累。
- 每个算法在独立的 128 MiB 数值线程中运行，不重叠窗口，每个窗口最多 200 万压力值、计算最多 3 秒；最多同时运行 8 个算法。计算跟不上时停止该分类实例，不堆积无限队列，不中断采集。
- 当前界面显示真实类别名称及阶梯趋势，例如“抚摸”“拍打”“未知”；编号不是概率。首个窗口不足时显示积累进度，断流、倒序、点数/阶段不匹配时显示错误。切换系统、进入回放、授权失效、删除绑定或停用都会释放实例。
- 包 ID 为 `user-<保存版本 ID>`，限定在测试并保存的系统使用。原生独立系统支持持久绑定和图表；算法超市可临时启用。通用 Manifest 的 Python 包导入器不会把受限分类器作为完整 Python 包导入。
- 旧版保存算法没有 `inputContract` 时，Agent 能读取原源码，并在用户选中的数据上重新测试、保存新版本后接入；不需要重新编写。没有数据选择时只需重新选取记录，已有标签会复用。

## 9. 生成系统的调节与工具

Agent 生成的 Manifest 矩阵系统复用监测页的调节和工具入口，已有系统也会随页面代码更新获得这些能力，无需重新生成系统。切换视图后，面板按当前渲染器实际支持的项目更新。

- **3D 点图**：颜色、高斯、连贯性、过滤、高度和总和门槛；工具区可旋转、俯视、缩放、恢复视角、框选分析及传感点量尺。物理距离需先设置实际点间距。
- **柔和热力图与热力图**：颜色、高斯、连贯性、过滤和总和门槛；不显示没有接入的三维工具。
- **原始蓝色数字矩阵**：保留原始读数，只提供适用的颜色调节。

调节只改变画布显示，不改线序、采集数据或算法输入。过滤调低后立即从原帧缓存恢复；高斯设为 0 表示不模糊。规则矩阵的 3D 点图和柔和热力图已统一主对角线方向，有效物理点位表仍保留其真实形状。
