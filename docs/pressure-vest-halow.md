# 压力传感背心（HaLow）

2026-10-20 合入 `agent` 后，接收与控制入口位于 `backend/kernel/transport/halowReceiver.js` 和既有 HTTP 命令路由，统计位于 `backend/extensions/built-in-sensors/pressureVest.js`；前端复用 `client/src/visualization/human-body/`。下文原分支的历史验收数据保留作参考，本次合并的实际验证以 `ARCHITECTURE.md` 当日记录为准，不代表已重新完成真机验证或发布。

系统 key：`pressureVest`；中文名称：压力传感背心；授权分类：`precision`（精密）。

## 使用

1. 使用包含 `pressureVest`、`@group:precision` 或 `all` 范围的有效密钥。在展示系统下拉框选择“压力传感背心”。固定只授权人体全身传感的旧密钥不会自动增加背心。
2. 进入“实时”，关闭已有串口，点击工具栏“HaLow 连接”。
3. 选择电脑连接 HaLow 网关的本机 IPv4 地址和 TCP 端口（默认 `12345`），开启接收。B 板继续使用已配置的网关网络，并主动连接上述电脑地址。
4. 在在线设备列表选择目标 ID。一次显示一块 B 板，不合并不同设备的数据；重复在线 ID 会被拒绝。
5. 使用“3D皮肤”查看同一人体模型上的胸、背、肩压力，或使用“原始数据”的正面/背面按钮查看对应网格。设置中的色阶和过滤只影响可视化，左侧统计使用实际点位的原始值。
6. 原采集、回放和 CSV 下载按钮继续可用。采集或回放期间不能开启连接或更换设备；停止接收始终可用。断线/停止清空实时显示，清屏消息不写入采集记录。

密钥发证服务的共享目录需要同步新增项，操作见 `license-key-values.md`。本次没有发布或修改外部发证服务。

## 数据协议与点位

- ID 帧：`AA 55 00 LL + ASCII ID`。
- 数据帧：`AA 55 03 99 + 1024 字节 uint8 ADC`。TCP 接收器按连接分别缓存并拆帧，支持分包、粘包。
- 点号是 `1..1024`，点号 `N` 对应原始数组 `frame[N - 1]`。
- 前胸：18 行 × 10 列，180 点。每行左侧 5 点与右侧 5 点之间留一列宽的拉链空隙，空隙没有通道和值。
- 后背：22 行 × 10 列，220 点；第三行包含 `69,68,67,66,65,79,78,77,76,75`。
- 左右肩：各 6 行 × 3 列，各 18 点。正面显示后三行，背面显示前三行并按背面观察方向反转行列。
- 全部 436 点互不重复。以用户的两张网格图为准，文字中的重复行只保留一次。
- 前后端共用的唯一通道映射：根目录 `pressureVestSensorMap.json`；前端模型和网格布局由 `client/src/components/video/pressureVestConfig.js` 派生。原始数据格同时显示点号和压力值。

前视屏幕左侧是右肩，第一行为 `1021,989,957`；屏幕右侧是左肩，第一行为 `792,760,728`。后视屏幕左侧是左肩，第一行为 `727,759,791`；屏幕右侧是右肩，第一行为 `958,990,1022`。

模型复用人体全身传感的 `model/human3-low.glb`，失败时回退 `model/human3.glb`。胸、背物理位置按现有 `model/sensor_canvas_positions.json` 表面网格插值；肩带独立按图片的前后3×3布局拟合，再投影到实际加载的模型表面。压力值直接来自单一原始通道。模型模式没有手臂或裤腿传感点；背景人体仍保留完整外形。

## 肩带三维布局

旧人体肩区跨过颈根，不能直接用于新图中的背心肩带。例如左前肩 `#794` 原位置X仅约0.042，接近身体中线，因此前肩内侧热力会集中在脖子附近。

现在前肩使用源矩阵后三行，后肩使用前三行倒序，分别与胸、背网格的前三行同高。每侧三列沿胸背外缘向肩外侧铺开，左肩为人体的正X侧，右肩为负X侧；源通道、二维网格及400个胸背点保持原位置。模型完成高度8的归一化后，前肩从正Z、后肩从负Z投影36点到当前GLB，不增加悬空偏移；若无法命中对应表面则报错，避免继续使用颈根布局。

图片提供的是展开网格和通道顺序，没有服装物理尺寸。当前三维位置是据此贴合人体模型的可视化布局，仍需实际逐点按压核对覆盖范围。

肩带修正验证：9项布局测试使用真实低模、高模核对各36点的表面命中、朝向、行列和胸背侧边界；400个胸背坐标的修改前摘要保持一致，旧肩档案移除后也能生成完整436点。原始网格、原始统计、水晶材质、顶点热力和渲染设置的45项相关测试及最终生产构建通过。浏览器以前后两面、水晶高效/正常档和左右肩三列及全肩测试28组，肩带已从颈根移至左右肩，四组热力清零差分均为0；原始网格编号与图片逐项一致，切回原人体1120点正常，无控制台或页面错误。截图和测试帧均为模拟，未重启真实软件或改变设备连接。

## 统计、采集与导出

左侧压力/面积使用 436 个唯一原始通道计算，两种显示模式一致。正值参与总量、峰值及有效点均值，面积沿用项目的非零点数表示方式；未新增力或压强单位标定。

采集与回放仍使用完整 1024 点原始帧，归零后的帧按既有采集逻辑保存。CSV 的 `realData` 保留这些原始通道，可按一基点号查找胸、背、肩；不重复映射、旋转或插值。历史压力/面积曲线和 CSV 峰值、压力及面积元数据只统计同一436个有效通道，未使用通道不会影响这些统计。

背心的模型设置保存在 `pressureVest.renderSettings.v1`，与人体全身传感的设置独立。

## 水晶模式正面热力修正

水晶“高效”档（`exact`）的正面材质由背面材质克隆。Three.js 会同时克隆传感数据纹理，实时帧更新原纹理的GPU版本却不会更新克隆版本，因此会出现正对胸/背看不到热力、转到反面能看到的现象。正面覆盖层现在显式共用原始 `DataTexture`；保持原有透明外壳、正反热力alpha及绘制次序。

几何核对使用与运行时相同的模型归一化：低模180胸点中，173点沿Z轴命中前后表面，全部更靠近前胸，前表面距离的中位约0.00025，而当前热力半径为0.1。剩余7点位于侧缘，未沿该方向命中。无需为上述纹理问题整体外移点位；侧缘插值的局部贴合精度仍与真机点位校准分别验证。

本次修复验证：36项相关单元测试及临时目录生产构建通过。固定视角的浏览器模拟中，水晶高效档中胸点 `#138=255` 的正面热色像素由0恢复为2722；后背控制点的正视热力也恢复。两侧视角均通过“零帧→按压→清零→另一点按压”，清零后的截图差分为0。普通热力与水晶正常档的基线保持一致。默认量程1555、过滤6下，前胸值41仍能显示淡蓝，100及255更明显；低值颜色较淡是原有量程与强度效果，不为此改动点位或数据。浏览器没有页面错误，真实软件没有主动重启，实物仍需刷新界面后核对。
