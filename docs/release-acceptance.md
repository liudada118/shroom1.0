# 打包后自动验收

发布前先运行源码 Full，再针对本次准备交付的解包目录运行验收。后者直接读取目标 `resources/app.asar` 和正式宿主优先选择的 `resources/build`，不会重新构建网页或从仓库借用生产模块。

```powershell
npm run verify:full
# 按项目原打包流程生成本次候选包，然后指定它的目录：
npm run verify:release -- --app-dir "C:\path\to\win-unpacked"
```

也可指定已安装应用目录，例如 `C:\Shroom`。该命令读取应用文件，不启动其正式主进程，不安装或卸载软件；不能直接传 NSIS 安装器 `.exe`。若要保证安装器里的内容与候选目录相同，还需要另做安装/解包及文件哈希对比。

需要构建机的 npm 依赖、Electron Node runtime 和 Chrome。默认使用本仓 Electron 来加载指定产物模块并验证原生 ABI；可通过 `--electron "C:\path\to\electron.exe"` 明确更换运行时。脚本在启动前检查 RunAsNode fuse，禁用时直接拒绝，避免误启动正式软件。报告记录实际运行时路径、Electron/Node版本、ABI和生产模块来源；这不是“随包主进程已启动”的证明。

## 当前自动流程

连接识别新增独立检查：`node scripts/tests/serial-detection-portal.mjs` 在真实Vite门户中验证默认连接先正式读取、两秒无有效数据后识别、非默认结果确认、未知/不兼容/歧义不自动重连、关闭取消与迟到结果隔离，并检查波特率输入和延迟提示。HTTP/WS均为夹具，真实五档字节识别、半包门槛、端口占用与驱动迟到关闭由 `backend/tests/serial/serialProtocolProbeService.test.js` 覆盖；这两层不能代替实体串口驱动验收。Full会执行后端识别、HTTP及前端状态测试；浏览器专项需显式运行，不应把它算成当前产物验收脚本的自动步骤。

fast256现在默认921600。原生支持入口先按默认参数正式连接和读取，当前连接两秒无有效数据时才按默认优先识别五档波特率；非默认结果经确认使用，未知协议不会自动替换业务解析器。特殊入口及manifest沿用声明配置。源码13种模拟配置已复验，报告 `shroom-release-acceptance-kwlbIJ/report.md`；当前26类门户交互报告为 `shroom-serial-detection-portal-qp5RdB/report.json`，旧宿主默认值补验报告为 `shroom-baud-bounds-cH1Lcn/report.json`，均位于系统TEMP，未打包或验证实体设备。

| 层 | 实际检查 | 判定依据 |
| --- | --- | --- |
| 产物身份 | ASAR SHA-256、应用版本、前端 buildId/版本、运行依赖和本机配置隔离 | 缺失、不匹配或运行中ASAR变化即失败 |
| 连接及采集门槛 | 真实 SerialManager + parser，模拟物理串口；真实 HTTP `collection.control` | 未连接、端口已开但无有效帧、错误长度帧均不能开始采集 |
| 采集保存 | 下表13种配置，分块输入非对称帧，真实SQLite批写和会话日志；手套使用正式左右同库分表 | 停止后排空；实际帧数、每点值、手侧与保存回执一致；停止后的新数据不入旧记录 |
| 回放及CSV | 读取同一临时库，生产回放服务和实际CSV文件 | 共70帧、48,640个压力值与80个手套存储姿态值逐项对比；矩阵清屏尺寸符合各配置 |
| 异常结束 | 时间推进模拟5秒断流、端口close模拟拔线 | 采集停止、已收数据排空，重新来数据不能自动重新采集 |
| 编译网页 | 目标包内实际HTML/JS/CSS，通过Chrome访问；HTTP/WS使用隔离夹具 | 64×64页面真实GPU上传无无效数值，压力总和正确，短帧/完整清屏后正常显示，无页面异常/资源404 |
| 分包跨入口 | `fast256`实际编译门户消费前一组件步骤产生的手套分包实时/数据库回放帧 | 10帧、每帧256数字从真实GPU UV上传还原后逐项一致，侧栏总和一致；没有组件证据时明确未运行 |
| 公司目录 | 目标包内实际门户，两种可控响应顺序 | 重复相同授权快照不丢同步结果，迟到旧空目录不隐藏已同步公司卡；不进入公司系统或调用后台授权服务 |

每项失败返回非零退出码并继续检查其他独立层。报告写入系统临时目录，命令最后输出路径；包含 `report.md`、`report.json`、模块运行日志、模块来源列表、临时SQLite、CSV及页面截图。用 `--output <尚不存在的新目录>` 可以指定保存位置。不要把测试数据库当客户采集记录。

```powershell
# 开发期只跑当前源码的生产组件链，不代表安装包验收：
npm run verify:release -- --source

# 无浏览器环境只检查产物身份和组件链，报告明确网页未执行：
npm run verify:release -- --app-dir "C:\path\to\win-unpacked" --skip-ui
```

旧版本如果没有验收需要的生产模块，会报告 `ACCEPTANCE_API_UNAVAILABLE`。这表示该版本未完成这条验收，不能把它说成已通过，也不能仅凭此错误断言旧应用本身缺依赖。任何依赖逃逸到目标目录以外都会失败，禁止缺模块时改用仓库新版代码“补过”。

## 已有模拟设备

这是测试进程内部的串口替身，驱动目标包的正式SerialManager、parser和协议处理器，不在Windows串口列表中创建COM口。

| 设备 | 系统标识/配置 | 字节协议及额外检查 |
| --- | --- | --- |
| 32×32矩阵 | `fast1024` | 1024字节，标准帧尾，5帧 |
| 64×64高速 | `bed4096num` | 4096字节，标准帧尾，5帧 |
| 16×16高速 | `fast256_plain` / `fast256_glove_segments` | 普通256字节与手套130+146分包分别进入真实legacy串口分派；各5帧，半包拒采；回放清屏恰好256点 |
| 手部检测 | `hand` | 1024字节，标准帧尾；独立接线索引验证jqbed线序，5帧 |
| 小床12B | `smallBed12B`：32×32，以及16×16左上/右上/左下/右下采样 | 2048字节、1024个UInt16LE；专用帧尾；非零基线先扣零、正式V2.7.54标定、kPa存储、防止重复标定/转置，每配置5帧 |
| 触觉手套单手 | `hand0205`：左手、右手分别验证 | 130+146字节分包，每手256个压力值+4个Float32LE姿态值；首半包不能采集，每配置5帧 |
| 触觉手套双手 | `hand0205Double` | 左右两串口交错首尾包，验证手侧身份、存储分表和合并CSV；每手5帧 |

标准帧尾为 `AA 55 03 99`，12B专用帧尾为 `AA 00 55 00 03 00 99 00`。脚本刻意将尾标拆到两次写入，并覆盖错误长度、未连接、连接无有效数据、断流和断连。报告按配置列出帧数、比对点数和实际数据库/CSV位置。

小床、手部、手套专用入口场景验证数据组件链路；编译网页自动操作覆盖64×64、公司目录，以及手套分包接16×16高速入口。12B未覆盖“实时显示32×32、仅采集另降为16×16”的独立采集选项；手套未覆盖整包型、115200变体、自动按包内手侧路由或解剖模型准确性。fast256历史按矩阵语义只保存压力，不把它当作手套姿态历史。

实体设备仍须匹配波特率：fast256默认921600，与分包手套常用速率一致；若设备使用其他速率，可在波特率输入框中修改，或在无数据识别后确认匹配结果。模拟字节输入不能验证真实驱动的波特率匹配。

## 尚需单独验收

报告的 `passed_for_listed_scope` 只对应上表已执行的项目。完整Electron主进程与IPC、NSIS首次安装/升级/卸载、真实USB串口驱动、长期高频采集、采集限频策略、其他型号/多路设备及线上公司授权均未由此脚本覆盖。模拟串口不能代替实体设备。

完整exe自动操作应放在隔离Windows用户或虚拟机中做，避免正式应用固定端口和真实userData互相干扰；本轮没有新增生产授权旁路或测试开关。正式交付前，还需用实际设备做连接→采集→停止/断连→回放验收。只有明确测试过的系统、包、硬件及场景才能登记为通过。
