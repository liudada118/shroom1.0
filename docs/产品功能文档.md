## 1. 产品概述

Shroom 是一款面向压力与触觉传感器的桌面软件。用户可以选择对应展示系统，连接串口设备，查看实时压力分布与统计结果，保存采集数据，再进行历史回放和 CSV 导出。

软件同时提供展示系统配置器和内置 Agent：配置器用于定义传感器接入、点位映射、算法和画面；Agent 通过对话读取软件状态、准备配置方案和设备连接方案，由用户应用后执行。

当前功能覆盖四类场景：

| 场景分类 | 典型对象 | 主要用途 |
| --- | --- | --- |
| 康养监测 | 床垫、床褥、足底、宠物看护垫 | 压力分布、专项算法指标、采集与回看 |
| 座椅感知 | 整椅、轮椅、座椅与靠背 | 多区域压力观察 |
| 具身触觉 | 手部、触觉手套、机器人触觉上衣、人体模型 | 点阵或三维模型上的触觉展示 |
| 定制系统 | 通用矩阵、定制传感器、已安装展示扩展 | 按配置接入和组合展示 |

上述分类是首页的产品导航，不是账号角色或权限等级。实际可见系统取决于授权范围和本机已加载的配置。

## 3. 主要使用流程

### 3.1 实时监测与采集

1. 启动软件，验证授权密钥。
2. 在首页按分类或名称找到系统，查看预览并进入。
3. 在监测控制栏选择各传感器对应的物理串口。
4. 确认画面持续收到实时数据，检查点位方向和数值变化。
5. 按需设置视图、图表和压力零点，开始采集。
6. 结束采集后，在历史记录中回放或导出。

“已进入系统”“串口已打开”和“收到有效实时数据”是不同状态。首页预览不是设备数据，串口打开也不代表协议、线序或物理点位已经正确。

### 3.2 历史数据查看

1. 结束正在进行的采集。
2. 打开回放记录弹窗，选择一条记录用于回放。
3. 使用播放、暂停、进度和速度控件查看过程。
4. 需要导出时，独立勾选一条或多条记录并配置 CSV 选项。
5. 查看导出状态和文件结果。

### 3.3 接入定制传感器

1. 从工具箱进入“展示系统配置”，新建草稿。
2. 配置传感器身份与数据通道，选择协议预设或手动填写参数。
3. 导入坐标 JSON，检查线序、矩阵形状与点位方向。
4. 选择数据处理方式、渲染器、配色和统计图表。
5. 先用“1-N 测试数据”检查排列，再用实时数据检查接入。
6. 点击“保存并显示”，加载系统后连接实际设备。

也可以向 Agent 提供协议和点位附件，让它准备创建方案。Agent 创建与配置器保存的后续行为不同，详见第 11 节。

## 4. 授权、首页与工作台

### 4.1 授权与系统选择

- 首页按“康养监测、座椅感知、具身触觉、定制系统”组织系统。
- 支持按名称或系统标识搜索，以及选中系统后的场景预览。
- 内置系统列表依据服务端已验证的密钥范围过滤；未知授权状态不会按全量授权处理。
- 已发现的自定义系统按配置加入列表；当前首页规则将其作为独立安装入口处理，进入业务仍需通过相关运行检查。
- 预览和搜索不发送设备连接或采集命令，确认进入才触发相应授权与系统切换流程。
- 授权失败、过期或换密钥后，按返回结果更新可访问入口。

### 4.2 监测工作台

工作台以中央数据画布为核心，组合监测控制栏、快捷工具、统计图表和设置弹层。用户可以显示或隐藏图表，收起快捷工具，打开算法超市、调节面板和工具箱，并返回系统选择界面。

“系统专用工具”根据当前系统与显示模式展示设备校准、曲线、重心或报告等操作。按钮不存在或不可用，可能是当前渲染器未提供能力，不表示所有系统都支持该功能。

## 5. 设备接入与数据处理

### 5.1 单路与多路设备

软件根据当前展示系统配置串口角色。例如座椅可能包含坐垫、靠背和头枕，手套或足底可能包含左右两路；自定义系统则使用逐传感器配置的身份和通道。

用户选择本机实际串口后发起连接。自定义系统可以为不同传感器保存不同的协议、矩阵、算法和存储开关；多路通道在同一展示系统内保持独立身份。

支持刷新串口列表和按角色打开、关闭端口。切换系统会关闭原有串口并切换运行配置；修改波特率后需要重新连接才能生效。

多串口并发接收不等于设备具备硬件同步采样。严格同步需要硬件时钟、触发或时间戳支持，本文不承诺跨设备同步精度。

### 5.2 协议与映射

配置器提供协议预设，并可调整波特率、数据精度、分帧方式、帧长或分隔符、帧头和校验项、数据偏移等参数。系统按照协议解码，再按线序和点位配置组织数据。

“一键识别”会临时读取选定串口，在当前目录中可探测的协议预设内匹配。它不生成任意新协议，不识别“左手、右手、靠背”等业务角色，也不将临时 COM 路径保存为系统定义。无匹配或存在多个候选时，需要用户继续确认配置。

线序描述采样值的读取顺序；坐标描述点在画面中的位置。两者配错可能仍有画面，但物理位置与数据含义不一致。

### 5.3 压力清零与显示变换

“压力清零”以当前数据建立零点基准，可取消零点处理。它属于数据处理能力，不是压力单位标定，也不应等同于颜色或视角调整。

归零逐点减去基准并将负值截为 0，没有有效数据时不能建立基准。零点状态保存在运行内存中，不承诺跨重启保留；门户回放模式禁用清零和取消清零入口。

旋转、缩放、水平和纵向翻转属于当前画布的显示操作，不改变原始数据、采集或导出内容。归一化、阈值过滤和邻域平滑等可视化处理也应与后端采集前算法区分。

### 5.4 串口异常提示与恢复

普通与自定义通道连接时显示加载状态，等待实际打开结果后才显示选中串口；连接中不能重复选择。错误提示包含对应通道与 COM 路径，连接失败或设备断开时清除连接选择，失败原因保留在连接栏下方。

| 场景 | 用户反馈与处理 |
| --- | --- |
| 扫描不到设备 | 提示检查 USB 连接与驱动；有串口但未通过筛选时说明未发现符合条件的 WCH/CH34x 设备 |
| 串口被占用、访问被拒绝或设备已拔出 | 提示释放占用、检查权限/驱动或刷新设备列表；不会关闭另一通道来抢占端口 |
| 打开失败或连接超时 | 显示失败原因，允许手动重试；物理打开默认超时为 10 秒 |
| 意外断连或通信异常 | 提示检查连接；启用重连的通道每 3 秒最多自动尝试 3 次，失败后停止并提示手动重试 |
| 已打开但无数据 | 持续 5 秒没有收到字节时提示检查设备是否开始发送 |
| 收到字节但无法形成完整帧 | 持续 5 秒无完整帧时提示检查设备、波特率和协议配置 |
| 连续坏帧 | 已配置协议校验的通道连续 10 帧校验失败时提示检查配置；未声明校验的设备不推测此类错误 |
| 关闭失败 | 显示资源释放失败提示；未确认释放的物理路径暂不允许被新连接占用 |

同一故障的 HTTP 回执与状态广播不会重复弹出提示，后台重试不会持续刷屏；收到正常数据后清除数据告警。主动关闭会停止重连。连接超时或取消后若驱动迟到返回打开成功，软件会立即关闭该端口。

这些检查不能证明线序、点位映射或物理量标定正确。敏枕附加文本传感器目前只检查字节是否持续到达；普通连接不新增 MAC 查询或波特率自动探测。

## 6. 实时展示与交互分析

### 6.1 展示方式

| 展示方式 | 用户看到的内容 | 使用范围 |
| --- | --- | --- |
| 热力图 | 以颜色表达数值分布 | 通用矩阵及配置式展示 |
| 数字矩阵、原始二维数据 | 逐点数值与行列排列 | 排查点位、查看原始空间结构 |
| 点阵热力、斑点热力 | 点或斑点组成的压力分布 | 支持的 SDK 渲染器与系统 |
| 手部、手套、机器人或人体模型 | 在专用模型或点位布局上显示触觉数据 | 对应内置系统，依赖专用映射和资源 |
| 多组件画布 | 多数据视图和统计组件组合 | 配置式系统，可分别绑定传感器来源 |
| 已安装扩展渲染器 | 扩展提供的主画布或图表 | 已通过安装检查并被配置引用的扩展 |

配置器当前通用渲染目录包括热力图、数值矩阵、原始二维数据、数字矩阵、3D 点阵热力、WebGL 斑点热力和 Canvas 2D 斑点热力。专用手套与人体模型不能据此推断为任意矩阵的通用渲染选项。

### 6.2 配色、叠加层与图表布局

配置式系统支持选择配色及反转色带，组合数值标签、网格线、图例、坐标轴和峰值标记等目录项。实际生效范围由渲染器决定。

内置系统的调节面板还会按模式提供平滑、颜色、过滤、高度、点大小、一致性、初值等参数，不同系统的选项并不完全相同。

画布配置器支持通过点击或拖放加入显示组件、调整顺序、移除组件和选择数据源；图表配色、图表叠加层与图表卡片可单独配置。部分工作台偏好保存在本机，不代表自动同步到其他电脑。

### 6.3 视角与框选

- 支持的画布提供旋转、俯视、放大、缩小、恢复视角以及水平、纵向翻转。
- 框选分析可建立多个矩形区域，编辑名称和矩阵坐标，拖动区域、通过边角调整尺寸或使用键盘移动与删除。
- 接入公共框选接口的点图和原始规则矩阵使用原始采样索引统计；多个区域的重叠点按并集去重。
- 当前视图不满足安全映射条件时，框选禁用；旋转或镜像后可能需要先恢复视角。
- 框选与量尺互斥，退出框选会按当前工具逻辑清理选择。

### 6.4 传感点量尺

用户设置横向、纵向相邻点的中心距，单位为毫米，然后选取两个传感点测量平面中心距离。支持拖动整条线或端点、键盘调整、删除，最多同时保留 8 条量尺。

点距按系统及矩阵尺寸在本机保存。未设置点距时只显示跨格信息，不生成毫米读数。量尺测量的是采样点平面距离，不是屏幕像素距离、压力高度或三维曲面长度；缺少可靠点位映射的画布不开放该能力。

依据：[工作台工具](../client/src/page/licensePortal/PortalWorkspaceTools.jsx)、[框选工具](../client/src/page/licensePortal/PortalSelectionTools.jsx)、[传感点量尺](../client/src/page/licensePortal/PortalScreenRuler.jsx)、[渲染目录](../backend/extension-host/manifest/displaySystemRendererCatalog.js)。

## 7. 统计图表与算法超市

### 7.1 压力统计

常见统计项包括压力总和、平均压力、峰值、有效点数、受压面积及对应趋势。它们由当前数据与配置计算，名称相同不一定代表统计范围完全一致。

| 指标 | 当前常见计算口径 | 使用时注意 |
| --- | --- | --- |
| 总压力/原始数据总和 | 当前输入数组求和 | 未经标定的数值不能直接视为力或实际压力单位 |
| 峰值 | 当前输入数组的最大值 | 取决于当前帧、选区及数据处理阶段 |
| 有效点数 | 大于指定阈值的点数；基础模板为大于 0 | 阈值不同会改变结果 |
| 有效点占比 | 有效点数除以总点数，再转为百分比 | 基础矩阵图表支持 |
| 受压面积 | 有效点数乘以配置的单点面积 | 单点面积、阈值及单位必须与传感器一致 |
| 平均值 | 基础“原始数据平均值”为所有点之和除以全部点数 | 配置式侧栏 `averagePressure` 为总和除以有效点数；部分旧视图沿用各自口径 |
| 中心区域压力 | 矩阵中间 50% 矩形区域求和 | 需要原始矩阵输入 |

### 7.2 图表与算法输出

算法超市按当前系统提供可用模板，用户可以点击或拖入图表，也可以移除已添加卡片。具有原始矩阵的视图提供矩阵计算；只有汇总统计的旧视图使用已有统计值，不把缺少的矩阵补成零值。

系统已经声明的算法指标也可进入趋势图。目录中出现某个名称，不表示当前传感器已经产生有效结果；应结合数据状态判断。

Python 算法包可按当前传感器启用或停用。关闭超市面板后，已启用的结果仍可展示；换系统后需要重新选择。启用受授权、内置保留任务、实时数据和输入兼容性等条件约束。

算法超市旁路消费实时数据，不消费历史回放；它的输出趋势不自动进入采集记录或 CSV。将算法包配置到系统主处理链，与临时从超市启用分析，是两种不同用法。

### 7.3 内置 Python 算法包

| 算法包 | 主要输出 | 配置目录中的适配条件 |
| --- | --- | --- |
| 床垫生命体征 | 呼吸率、心率、在床状态、告警相关字段、重心、体动等 | 1024 点，建议 32×32；目录建议输入 50 Hz |
| 足压实时重心分析 | 左右脚压力、面积、COP 坐标和速度 | 4096 点，建议 64×64；目录建议输入 20 Hz |
| 宠物看护呼吸检测 | 呼吸率、姿态、体动、信号质量、离床标志、压力系数 | 1024 点，建议 32×32；目录建议输入 50 Hz |
| 宠物看护 Mini 呼吸检测 | Mini 看护的呼吸、姿态、体动和质量等指标 | 1024 点，建议 32×32；目录建议输入 50 Hz |

这里的频率是算法目录建议条件，不是整机吞吐或测量精度承诺。算法包的具体输出、资源依赖和运行状态仍需满足要求。

床垫包当前输出呼吸率单值，不提供呼吸波形；`-1` 和 `88` 等检测状态不能当作正常测量值。压力趋势、呼吸率趋势和呼吸波形是不同数据，不应通过修改图表名称混用。

依据：[图表模板](../client/src/components/aside/formulaChartTemplates.js)、[统计实现](../client/src/extensions/display-system/displayProfileRuntime.js)、[算法超市目录](../client/src/page/licensePortal/portalAlgorithmCatalog.js)、[算法包目录](../agent-resources/algorithm-packages/README.md)。

## 8. 采集、回放与导出

### 8.1 采集记录

实时模式提供开始和结束采集操作，并显示采集状态与时长。可设置记录名称和两组特征标签；记录按名称或开始时间组织。数据保存在本地数据库，供历史回放和导出使用，自定义系统可逐通道设置是否参与存储。

后端初始采集模式为“串口全速”，自定义频率默认值为 12 Hz，可设置范围为 1–200 Hz。该范围是调度配置范围，不表示设备必然达到对应采样率。

采集保存的是经过当前有效处理链的可存数据。协议解码、线序、后端算法和零点处理可能已发生，不能将所有记录统称为原始串口字节。设备采样率、算法输出率、存储率和画面刷新率也不应混为一个指标。

结束采集会刷写已积累的最后一批数据。磁盘空间不足或数据库报满时有停止采集和错误反馈逻辑；这不构成长时间运行零丢失的性能保证。当前采集设置没有开放矩阵降采样开关。

### 8.2 历史记录与回放

记录弹窗支持按名称或时间搜索、分页、刷新和全选筛选结果。回放使用独立的单选操作，CSV 下载使用多选操作；修改下载勾选不会自动替换当前回放记录。采集期间不能直接切入回放，需要先结束采集。

当前门户载入所选记录后会自动从头播放，并将速度恢复为 1×。支持播放、暂停、点选或拖动定位、开始与结束区间手柄，以及 0.25×、0.5×、1×、1.5×、2× 速度。

1× 根据历史时间间隔估算原始节奏，不保证逐帧复刻任意不规则采样时刻；多路数据按时间锚点选取相近帧，忙时可能合并显示推进。回放不会再次录制，也不会重新执行配置式系统的主链路算法。

删除操作仅针对当前单选记录，并要求确认；下载勾选不决定删除对象。删除后无回收站，无法通过软件恢复。

### 8.3 CSV 导出

- 支持单条和批量导出，批量按记录串行执行，并显示进度、成功文件与失败信息。
- 批量导出使用每条记录的完整会话，不沿用回放区间；其他历史导出路径可能沿用当前区间，以入口配置为准。
- 支持配置路径，在桌面环境选择或打开目录；多通道历史按通道分别生成 CSV。
- 明确的单条失败可继续处理后续记录；结果不确定或超时会停止后续任务，不自动重试。
- 当前导出格式为 CSV，不是原生 XLSX；使用 UTF-8 BOM 便于 Excel 读取中文。

常见导出内容包括相对时间、时间标记、最大值、受压点数、压力汇总和逐点数组。配置式多传感器记录还包含系统、传感器、通道和历史串口身份信息；具体字段随历史格式变化。

导出以历史实际保存的数据为准。`realData` 不保证为未处理设备原值，`pressureArea` 列在当前导出实现中是超阈值点数，不能直接解释为平方厘米。CSV 也不是算法超市趋势或全部算法指标的通用导出器。失败时可能已有部分文件生成，应核对返回文件清单。

依据：[采集服务](../sdk/backend/collection/collectionService.js)、[回放调度](../backend/kernel/playback/playbackTimerService.js)、[历史记录弹窗](../client/src/page/licensePortal/PortalPlaybackDialog.jsx)、[回放进度](../client/src/components/progress/Progress.jsx)、[CSV 服务](../backend/kernel/csv/csvDownloadService.js)。

## 9. 专项系统功能

专项能力只在对应系统、显示模式及数据条件下生效，不作为所有系统的统一承诺。

### 9.1 床垫与看护

小床监测（`jqbed`，以及保留的 `smallBed` 路径）可显示呼吸、心率、在床/离床及计时、坠床/坐起状态和 SOS。相应状态有语音提示调用；具体结果取决于型号、处理器与算法输出。

`jqbed` 的算法参数配置仅在该系统实时模式开放，提供 SOS、基础、滤波和高级参数组，以及读取、保存、重置操作。温度全床系统提供平均温度和逐点温度显示，单位为 ℃。

宠物与 Mini 看护页面显示呼吸、姿态、在离床、体动、信号质量和压力系数等信息。

**宠物页面的心率需要单独解释：** 当前前端在收到宠物相关数据但缺少后端 `heart_rate` 时，可能根据有效呼吸状态生成模拟心率；若后端明确提供心率则保留。不能将页面所有心率读数宣称为传感器实测结果。

算法字段与图表的存在，只能证明软件提供该处理和展示路径；本文未验证生理指标的准确度，也不据此承诺诊断能力。

### 9.2 OneStep 历史报告

PDF 报告入口限定于 OneStep（`bed4096`）的回放模式。用户选择历史记录，填写姓名、年龄、性别等信息后，系统获取不少于 4096 点的峰值帧并生成热图，再请求 PDF 生成；成功后展示保存位置并提供打开目录操作。

这不是全部足底系统的通用报告能力，也不等同于任意数据或任意时间段的报告编辑器。

### 9.3 足底、座椅及三维触觉

足底类代码有专用压力与重心分析路径；保留的 `foot` 页面提供重心显示与轨迹组件，但不能据此认定当前所有足底入口均具备相同工具。座椅和轮椅按照各自通道显示压力；手部、触觉手套、机器人触觉上衣和人体系统使用对应模型、点位和校准逻辑。

部分遗留页面还展示气囊充放气的外部控制状态。已核对的状态列表不是手动控制按钮，因此本文不将它列为通用轮椅气囊控制功能。

这些专用页面的功能与通用矩阵配置不是一一对应关系。复制一个矩阵系统不会自动获得原生三维模型、呼吸算法、气囊控制或足压报告。

依据：[专项显示与宠物心率处理](../client/src/components/aside/Aside.jsx)、[报告与专项工具入口](../client/src/components/title/Title.jsx)、[状态与语音流程](../client/src/page/home/Home.jsx)、[小床参数配置](../client/src/extensions/jqbed/jqbedAlgorithmConfig.js)。

## 10. 展示系统配置器

入口为工作台工具箱中的“展示系统配置”，另有独立配置页面。配置流程分为“数据接入 → 传感器映射 → 显示验证”。

| 配置区域 | 可配置内容 | 结果 |
| --- | --- | --- |
| 系统身份 | 系统 ID、显示名称、传感器类型 | 形成可识别的展示系统 |
| 逐传感器接入 | 传感器 ID、业务名称、独立输出通道、协议与存储开关 | 将多路数据分别接入和保存 |
| 协议配置 | 预设、自动探测和通信/分帧/解码/校验参数 | 确定数据如何解析 |
| 形状与映射 | 坐标 JSON、默认点序、自定义线序 JSON | 确定矩阵尺寸、点位和形状比例 |
| 后端处理 | 不处理、参数化数值处理、已注册 Python 包、可信 JavaScript/Python 函数 | 处理数据并按约定输出矩阵或指标 |
| 显示验证 | 1-N 测试数据、串口实时数据、渲染方式和画布预览 | 检查排列方向及实时画面 |
| 画布与图表 | 配色、叠加层、组件、数据源、指标与图表卡片 | 组合主画布及侧栏 |
| 保存 | 保存并加载配置，切换到对应系统 | 进入显示页面；实际连接仍需确认 |

坐标文件格式为 `rows × cols × [x, y]` 的 JSON 矩阵。导入后根据坐标结构推导矩阵尺寸和点位信息；物理坐标点数与线上协议点数应分别核对。

参数化处理包含缩放、偏移、低值清零与上下限等操作。高级函数编辑器提供 JavaScript 或 Python 入口及超时设置，面向理解数据契约的配置人员；当前内置 Agent 不具备任意代码生成或安装能力。

“保存并显示”会先保存、重载，再切换当前系统。内置只读配置不能直接覆盖；用户自建配置可按权限修改。保存成功不等于设备已经产帧。

已安装的 Agent App 可作为主渲染器或图表供配置器选择。这是展示扩展机制，与内置对话 Agent 是两个功能。现有扩展以只读传感器数据进行展示，不能据此推断它拥有设备控制权限。

依据：[配置器实现](../client/src/extensions/display-system/DisplaySystemBuilder.jsx)、[配置保存服务](../backend/extension-host/workspace/displaySystemWorkspaceService.js)、[扩展安装服务](../backend/extension-host/agent-apps/agentAppService.js)。

## 11. 内置 Agent

### 11.1 入口与模型配置

Agent 以全局对话抽屉提供，包含模型设置、会话消息、附件、任务步骤和方案卡片。完整功能依赖桌面软件的能力桥；单独打开前端页面不能代替桌面环境。

用户填写模型服务地址、模型名称和 API 密钥，服务需支持 Responses API 与工具调用。可以选择预设或输入模型 ID；实际可用性取决于所配置服务和账号权限。

### 11.2 当前可用任务

| 任务 | 可以做什么 | 执行边界 |
| --- | --- | --- |
| 查询状态 | 查询系统、通道、串口和连接相关状态 | 只读，不自动连接 |
| 查询能力 | 获取当前协议、算法和显示目录 | 基于实际注册信息准备方案 |
| 新建系统 | 使用已有协议、渲染器、完整线序及点位准备配置 | 每次创建 1–8 路完整传感器定义；先生成提案 |
| 复制系统 | 复制可读取的真实系统配置及映射、资源 | 使用独立身份；仅有旧页面而无配置的系统不能通过此工具复制 |
| 修改展示 | 修改可写系统的配色、叠加层、内置统计图表 | 不修改协议、映射或现有渲染 profile |
| 连接设备 | 为明确的系统、传感器和实际枚举串口准备连接方案 | 需应用提案；不猜测串口、不自动关闭原有连接 |
| 检查数据 | 有界观察指定通道，返回帧数、点数、来源与质量摘要 | 最多 10 秒、60 帧；无帧不等于设备损坏 |

内置图表修改工具当前支持总压力、平均压力、最大压力、受压点数和受压面积。它不能仅靠重命名生成呼吸波形或其他没有数据来源的指标。

创建或复制提案应用后会保存系统，不自动进入监测或连接设备；连接需要单独操作。连接提案还会检查授权、配置版本、现有端口和采集/回放状态，当前不支持所有遗留串口角色。

### 11.3 提案、恢复与中断

模型先生成方案卡片，用户查看摘要及配置后点击“应用此方案”，才执行相应创建、复制、修改或连接。应用前重新核对配置版本，避免覆盖已变化的系统。

已应用的展示修改在版本仍匹配时可“恢复此项更改”。创建或复制的新系统不会自动删除，设备连接也没有自动回退。停止任务只停止后续工作，不撤销已完成操作。

软件重启后恢复当前会话记录，将未完成任务标为中断，无法确认结果的写操作标为“需要检查结果”，不会自动重放。支持新会话归档，单会话最多 40 个任务；目前没有界面内的旧归档切换与删除管理。

### 11.4 附件与数据使用

| 项目 | 当前限制 |
| --- | --- |
| 附件格式 | TXT、Markdown、JSON、CSV、TSV、LOG、XLSX |
| 单文件 | 非空、最多 8 MiB；解析文本最多 120,000 字符 |
| 一次导入/任务附件选择 | 最多 6 个 |
| 一个会话 | 最多保留 12 个附件，合计解析文本最多 240,000 字符 |
| 单任务附件文本 | 合计最多 120,000 字符 |
| XLSX | 最多 8 个工作表、合计 12,000 个单元格，另有结构和解压大小限制 |

XLSX 使用文件中的缓存值，不执行公式、宏或外部连接。附件超限或不满足解析要求时拒绝导入，不会默默截断后当作完整点位资料使用。

所选附件的解析文本、本次消息、有限历史以及工具返回的状态或数据摘要会发送到用户配置的模型服务。实时检查可能包含少量传感器样本，不是持续转发全部高频数据。

API 密钥通过系统安全存储加密；消息、方案和附件文本以普通 JSON 保存在本机。当前没有软件内的模型充值、用户额度分配或金额硬上限。

### 11.5 当前不支持的 Agent 操作

- 自动采集、定时采集、批量导出或生成分析报告。
- 任意执行系统命令、自动生成新驱动、安装任意模型生成的可执行代码。
- 任意自定义图表或算法代码生成，以及切换现有系统的渲染 profile。
- PDF、图片 OCR、音视频理解。
- 自动恢复中断的创建或设备连接操作。

依据：[工具能力定义](../backend/agent-runtime/tools/toolSchemas.js)、[任务运行器](../backend/agent-runtime/runtime.js)、[模型设置](../app/electron/agentSettings.js)、[详细使用说明](embedded-agent.md)。

## 13. 能力边界与验收口径

| 项目 | 本文可确认 | 仍需单独验证或不能据此推断 |
| --- | --- | --- |
| 功能实现 | 当前源码中有入口、处理或配置路径 | 所有安装包、型号与运行环境均已通过验收 |
| 设备连接 | 有串口连接和状态管理 | 协议正确、持续产帧、物理点位正确 |
| 采集性能 | 有频率模式和存储路径 | 最高吞吐、长期零丢帧、固定端到端延迟 |
| 多设备 | 有多路身份、接入与显示 | 硬件同步采样或确定的同步精度 |
| 健康相关指标 | 有特定算法和展示字段 | 生理测量精度、临床有效性或诊断结论 |
| 宠物心率 | 当前前端含缺失值模拟逻辑 | 所有显示值均来自真实心率测量 |
| 量尺和面积 | 按点距、点面积及矩阵位置计算 | 未校准情况下自动得到真实物理尺寸 |
| Agent | 有模型调用、受限工具、提案和状态恢复 | 任意模型服务兼容、全自动操作或通用代码开发 |
| 软件扩展 | 可加载合法配置、算法与展示扩展 | 所有旧页面都能被复制或作为通用模板安装 |

面向交付的基本验收应选定具体系统、硬件、协议、配置和软件版本，至少覆盖：授权进入、真实帧与点位对应、采集停止、历史回放、导出内容、断连恢复，以及该系统实际使用的专项工具。Agent 还需单独验证实际模型服务与提案应用。

本次文档工作仅做静态源码核对和文档检查，未运行代码测试、完整构建、发布打包或真机实验。已有测试与历史验证记录可作为后续验收参考，不计为本轮实测。
