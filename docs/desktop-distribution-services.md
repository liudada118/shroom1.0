# 电脑授权、网页缓存更新与使用统计

核对日期：2026-10-15。本文对应 `agent` 分支源码；各项部署及实测范围见相应章节，本轮未制作客户安装包。

## 客户和管理员怎么使用

| 功能 | 入口 | 规则 |
| --- | --- | --- |
| 电脑数量 | 密钥网站 → 在线/离线密钥列表 → 电脑授权 | 默认 0＝不限量；只有 `super_admin` 可调整、解绑和恢复 |
| 网页更新 | 软件右下角 → 应用设置 → 网页更新 | 打包版启动 30 秒后检查，此后每 4 小时检查；可手动检查 |
| 使用统计与错误上报 | 软件右下角 → 应用设置 | 首次使用默认开启；设置告知上传范围并可关闭，关闭清除待传队列，升级保留已有选择 |
| 查看统计 | 密钥网站 → 使用分析 | 沿用现有超管页面与客户归属隔离 |

同一台电脑升级软件不重复占名额。系统安装标识在本机经过 SHA-256 处理，服务器只接收摘要，不接收原始硬件标识。系统重装、克隆系统或无法读取系统标识时的本地身份文件删除，可能改变或重复身份；这是电脑安装身份限制，并非防破解机制。

### 授权和断网

- 新版在线密钥首次需要联网验证。每次启动及运行中每 2 小时刷新授权；成功时保存绑定本机和密钥摘要、最长 7 天的签名凭证，并且不能超过密钥到期时间。断网时只接受尚未到期的有效签名；显式拒绝不会因断网改为允许。
- 0 表示电脑数量不限量，仍遵守在线密钥的到期及离线凭证规则。将不限量改为有限数量前，若已登记数量超限，需要先解绑多出的电脑。
- 解绑不是立即消除离线凭证：联网检查后拒绝，已经离线的电脑最迟在凭证到期后停止使用。授权失效时运行端停止采集、关闭连接，并返回可理解的授权原因。
- 已有不限量 RSA 离线码保留原来的纯离线规则，不能通过网站给旧码追加其签名中不存在的设备限制。需要限制时重新签发 **v4** 离线码；签入 `deviceLimit` 与 `boundSensorTypes`，首次联网登记后取得 7 天凭证。该码必须配合新版软件。
- 原来只执行本地授权验证的旧桌面版不能受新服务端数量规则约束，必须升级一次。老代码不能仅靠服务器或网页更新补齐这个主进程能力。

### 旧在线密钥未登记（2026-10-15）

旧 AES 在线码能在本地解密，并不代表已在当前服务器的授权库登记。旧服务端对此可能返回 `valid: true / UNKNOWN`，却没有电脑授权凭证；客户端现在明确提示 `LICENSE_NOT_REGISTERED`，由管理员补录原密钥，不能据此放行。其他成功响应缺少凭证时提示 `LICENSE_SERVER_UPGRADE_REQUIRED`；已经返回凭证但验签或绑定不符时仍提示 `DEVICE_LEASE_INVALID`。

配套服务器对带 `deviceId` 的未登记密钥返回 `valid: false / LICENSE_NOT_REGISTERED`，数据库不可用返回 503；无 `deviceId` 的旧版请求保留原兼容行为。管理员审核后的单把补录工具及默认预览步骤见 `E:/key/docs/desktop-distribution-services.md`。补录保留原串、系统范围及到期时间，不自动导入任意可解密密钥，也不恢复已暂停、吊销或删除的记录。

## 网页更新链路

```mermaid
flowchart LR
  A[本地安装包或已验证缓存] --> B[先启动当前页面]
  B --> C[后台查询签名版本清单]
  C --> D[复用本地资源并下载变化文件]
  D --> E[保存待启用版本]
  E --> F[下次启动加载]
  F --> G[应用确认启动成功]
  F --> H[失败则回退上一版或安装包]
```

本次实现的“联网缓存最新网页”是后台下载、下次启动启用。采集中不重载页面；无网或更新接口不可用时继续使用本地页面。安装包整体更新仍沿用原来的确认流程。

清单由公司系统包现有 Ed25519 密钥签名，客户端使用内置公钥验证。每个版本不可变，包含 `releaseId`、`buildId`、`minAppVersion`、`hostContract: 1` 和资源路径/大小/SHA-256。限制为 2000 个文件、单文件 64 MiB、合计 256 MiB；拒绝穿越路径、Windows 保留名称、大小写重复路径、重定向和哈希不符。

### 安装包优先级和缓存大小

- Vite 每次构建自动生成 `frontend-build.json`（构建毫秒编号 `buildId`、安装包版本 `appVersion`）。服务器把这个真实构建编号签入发布清单；`releaseId` 只决定发布顺序，重新发布旧构建不能让它变成新代码。构建电脑需保持正确时间，不要手工修改编号。
- 缓存必须通过签名、安装包最低版本和文件校验，且 `buildId` 大于安装包内网页的编号才能加载。安装包升级及相同版本重新打包均重新判断；比安装包更新且兼容的缓存仍可离线使用。旧清单没有构建编号时不能覆盖新安装包；安装包元数据缺失或无法建立缓存状态时使用安装包原页。
- 更新按大小和 SHA-256 查找本地可复用资源，包含改名但内容相同的文件；不匹配或已损坏时重新下载。缓存版本之间优先使用硬链接共享磁盘块，不支持时复制。安装包资源只复制，防止可写缓存损坏安装包兜底页；前端 JS/CSS 仍组成一份完整、统一校验的待启用版本。
- 混淆器使用固定种子，让未修改代码保留相同哈希。默认保护当前版、上一成功版、待启用版，以及确实还在运行的页面；其他数字版本目录和遗留下载临时目录自动删除。正常运行只需两份已验证版本和至多一份候选，文件锁导致清理失败时以后重试。
- 成功启用后才淘汰更老的回退版本；未确认启动、超时回退和活动文件损坏可回退上一成功版或安装包。已经失败的同一发布编号不会反复安装，修复时使用新的递增 `releaseId`。清理只作用于 `userData/frontend-cache`，不触碰聊天、采集数据库和密钥。

服务端也复用相同内容的已发布文件，并在发布成功后保留最近 5 个版本及最近 24 小时内的版本，保护客户端下载。宽限期内可能超过 5 个目录；客户端本地的完整缓存不依赖服务器永久保留旧版本。详细运维规则见配套仓库说明。

缓存启动时再次校验文件。待启用版本有启动标记，React 通过受限 IPC 确认启动后才成为已验证版本；30 秒没有确认时回退，异常退出后下次启动也回退。该确认表示应用外壳已启动，不代表每个功能或真实设备均已验收。

应用设置提供实际运行版本诊断：软件版本、宿主契约、安装包网页构建、当前网页构建和发布编号、安装包/缓存来源、候选外壳启动状态及最近回退时间/原因。不能把待启用版本当作当前运行版本；设备功能验收仍单独记录。

网页检查结果同时持久保存 `lastCheckedAt`、`lastCheckResult`、`lastErrorCode` 与本地白名单文案 `lastMessage`。服务器没有可用签名清单（最新版本接口 503）、安装包缺少构建标识、签名不通过、接口返回 HTML，以及已验签但宿主或最低安装包版本不兼容分别说明原因；重新打开设置仍可查看最近一次结果。未通过兼容性或完整性校验时不下载、启用候选代码，也不把失败显示成“已是最新”。

### 安装包网页标识与开发环境诊断（2026-10-19）

- `FRONTEND_PACKAGED_BUILD_MISSING`：当前选中的安装包网页目录没有 `frontend-build.json`。`FRONTEND_PACKAGED_BUILD_INVALID` 表示文件无法读取、JSON或schema/buildId无效；`FRONTEND_PACKAGED_BUILD_VERSION_MISMATCH` 表示文件中的appVersion与实际宿主版本不相同。`FRONTEND_CACHE_STORAGE_UNAVAILABLE` 单独说明本机缓存记录不能保存，不再误说包内文件缺失。
- 正式Mac默认位置为 `Shroom.app/Contents/Resources/build/frontend-build.json`，Windows为安装目录 `resources/build/frontend-build.json`；旧ASAR布局也按宿主实际候选读取。Vite从根package版本生成该文件，修改版本号后必须重新构建前端。Builder打包前与打包后校验源目录和最终Resources，并在缺失/非法/版本不符时失败；当前新增门禁未改变Forge内联配置。
- 真正缺少可信标识的旧安装包继续运行本地页，暂停网页更新。应重新构建并安装包含正确标识的完整安装包一次，不手写当前时间、远端buildId或直接改已签名`.app`，也不以删除用户缓存替代修复。
- 开发宿主明确传入 `isPackaged:false`，网页缓存服务返回 `source:development/updateSupported:false`。设置显示“开发版无需网页更新”，不会查询服务器、载入候选或改写生产缓存指针。该主进程修复需重启开发软件，单独刷新页面不重载Electron主进程；已安装客户端仍需安装包更新才能获得此分类逻辑。

`model/`、`models/`、`uv/` 等大模型资源继续使用兼容安装包中的文件，前端发布不混用安装包的 JS/CSS。网页需要新的 IPC、原生依赖、Python 能力或模型资源时，先升级安装包，并提高前端发布所要求的最低软件版本。更新错误或缓存损坏时保留本地可用页；修复发布使用新的递增版本 ID。

## 使用统计与错误上报

首次出现独立范围说明，记录已展示的说明版本；确认说明不修改默认开启状态，手动关闭选择跨升级保留。聊天上传、外部模型请求与统计的接收方和开关分别说明。约定使用统计保存目标为 90 天，实际服务端清理和删除以部署验收为准。

事件顶层可附带 `runtimeVersions` 白名单快照：`frontendReleaseId`、`frontendBuildId`、`hostContract` 为正整数，`systemPackageVersion`、`serverContractVersion` 为有限版本字符串。不包含路径、配置正文或原始帧；旧队列缺失此字段仍可恢复，已形成事件重试时保留原版本快照与 eventId，不能拿重启后的版本覆盖历史错误上下文。

已接入系统进入和停留、串口连接、采集、回放、CSV、Agent、后端公共日志、页面异常和 Electron 未捕获异常监视，并补齐下表中的业务结果。事件只带有限元数据，不在传感器每帧上传。

客户端发送到现有 `POST https://shroom.jq-industries.com/api/usage/events/batch`，以 `Authorization: License …` 鉴权。配套服务端同时支持已登记的在线密钥和有效离线 RSA 激活码；离线码须有有效客户关联、签发公钥并通过真实验签，纯本地可用但服务器未登记的码不能上传。来源由服务端确定，与 Agent 聊天同步开关和队列相互独立。

| 范围 | 实际记录 | 频率和结果含义 |
| --- | --- | --- |
| 数据调节与工具 | 平滑、过滤、高度、颜色范围、点大小、一致性、初始值、模型变换；归零/恢复、视角、框选、量尺与展示切换 | 滑块松手或键盘完成一次才记一次；数值不上传。关闭和禁用工具不记曝光。归零由后台完成后记录。 |
| 算法 | 手动启停、系统绑定结果、会话实例等待/运行/暂停/异常/停止、配置自动启动失败 | 每秒检查状态，仅变更时记录；自动启动相同失败不因每帧重试重复计数。不上传分类输入、源码或输出类别。 |
| Agent | 本轮方案生成、真正可见的方案、应用/恢复结果与耗时、成果入口及使用算法结果 | 读取历史不算新生成；折叠历史不算查看。连接方案没有验证到有效帧时记未知。点击进入只记发起，系统进入事件由实际页面确认。 |
| 设备数据 | 真实打开连接的首帧耗时、10 秒首帧超时、2 秒无帧及恢复、标准输出帧数/观测时长 | 实时且同系统同角色才计数，回放和授权暂停不算断流；每 30 秒汇总，关闭/切换时补短窗口。统计是标准通道输出帧，不是串口原始包数或丢帧率。 |
| 授权 | 激活/刷新、电脑授权核验、限额拒绝/凭证到期等有限错误码 | 按实际核验结果记录，不上传密钥、原始硬件身份或授权响应。没有有效上传密钥时不向服务器发送。 |
| 更新 | 网页检查/下载就绪/启用/缓存拒绝/回退；安装包检查、下载就绪、交给安装器和下次启动版本核验 | 不上报每个下载进度。安装器交接记未知；同一密钥下下次启动达到目标版本才记成功。网页下载数量字段的单位为字节。 |
| 采集回放 | 采集保存异常、完成时已提交的行数；回放加载、播放/暂停、倍速、跳转、阈值、模式及删除记录 | 事务回滚不计成功行；旧异步存储或未完成写入记未知。连续跳转/阈值/倍速修改合并 500 ms；记录名、标签、帧内容不上传。 |
| 系统操作 | 配置保存/编辑、复制/原生副本创建/删除、提交公司审核、同步及逐包安装结果 | 保持同步/异步原返回与错误；提交待审不算发布。没有收到服务器成功回执或实际安装失败时不算成功。 |

- 白名单事件与属性；不上传聊天正文、附件、采集标签、原始帧或自定义系统名称。自定义系统身份转为本机/密钥范围内的摘要。
- 错误文本在入队前清除已知凭据、URL、邮箱和本机路径；服务器继续校验和脱敏。错误摘要不是任意日志文件上传，也不包含崩溃转储或 Python 原始 stderr。
- 按密钥摘要隔离磁盘队列；每次最多 50 条，单条最多 4 KiB，每个密钥最多保存最近 2000 条。重新读取时只保留 30 天内合法事件，拒绝额外字段与重复 ID；满额丢弃最旧项。
- 30 秒执行一轮批次上传，达到 50 条可提前发送；同一时刻只发一批。埋点执行不直接逐项发网络请求，采样摘要及界面合并先进入原队列。
- 先异步落盘再上传，网络超时/限流/服务异常退避重试；明确的 4xx 拒绝停止自动重试，设置中可手动重试。只有服务器确认了这批所有 ID 才移除事件。同一 ID 内容保持不变，切换密钥不混发旧客户队列。
- 失败响应只读取最多 16 KiB JSON，按 HTTP 状态识别有限错误码，不显示服务端任意消息或 HTML。400 表示事件格式/接收契约问题，不提示更换密钥；401/403 才提示身份或授权检查，409/413 分别提示内容冲突/批次限制，429/5xx 自动退避。状态 `lastErrorCode/httpStatus` 只供有限诊断，成功、客户切换或关闭上报时清空。
- 服务端必须先部署可选 `runtimeVersions` 严格白名单，再发布携带该字段的宿主；旧版不带字段的 `schemaVersion: 1` 事件继续接收。整批校验失败会暂停该队列，不能删除字段后复用同一事件 ID 重传。修好接收端后在设置中“重试上传”；关闭上报会按原规则删除待传统计，不作为修复此问题的步骤。
- 重复错误每 30 秒汇总为新的计数事件；最多保留 128 种错误摘要，避免错误风暴挤占队列。关闭后删除待传统计文件，已送达数据不能从客户端撤回。
- 上传、写盘失败不会阻塞传感器处理；设置显示待传数量、最后送达时间和失败原因。重启保留队列，退避计时不持久化。

| 职责 | 文件 |
| --- | --- |
| 电脑身份 | `app/electron/deviceIdentity.js` |
| 授权签名校验与缓存 | `backend/kernel/platform/license/deviceAuthorization.js` |
| 实际授权入口 | `backend/kernel/platform/server.js`、WebSocket 命令适配器 |

身份、授权缓存、网页缓存、统计设置和队列均放在 Electron `userData` 下，不放在安装目录中。打包与 Git 排除相应运行时目录。
