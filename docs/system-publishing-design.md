# Agent 展示系统提交、发布与客户授权方案

状态：首期在线交付已实现于 `E:/shroom1` 与 `E:/key`，尚未部署到生产服务器。支持用户 Manifest 矩阵系统和原生模板副本；原生副本仍依赖客户软件内置的同一 `sourceType`。Agent 自定义渲染器、外部脚本/模型资源和离线授权文件尚未纳入交付包，导出时明确拒绝这类依赖。采集数据库、聊天记录与模型密钥不进入系统包。

## 当前可执行流程

1. 在密钥管理网站运行 `pnpm db:migrate` 应用 `0016_kind_puma.sql`、`0017_harsh_darkstar.sql`、`0018_brief_fixer.sql` 与 `0019_handy_gwen_stacy.sql`，并配置 `SHROOM_SYSTEM_PACKAGE_SIGNING_KEY_PATH` 指向**与桌面端 `systemPackagePublicKey.pem` 配对**的私钥。开发机私钥位于当前用户的 `.shroom/system-package-private.pem`；不得提交到仓库或放进安装包。生产服务迁移、私钥部署和 HTTPS 发布需由运维在目标环境执行，本次代码修改没有执行这些外部操作。
2. 员工登录管理网站“公司系统库”，生成 30 天限权提交令牌；在软件 Agent“模型设置 → 公司系统提交”保存一次。该令牌可提交待审包、只读获取已发布原包供本机修订；使用 OS 安全存储加密，不能发布或访问客户目录。
3. 新系统可在 Agent 成果卡片点击“提交公司审核”，也可在软件系统选择页选中本机可编辑系统后点击“提交公司审核”；“展示系统配置”列表仍保留同一入口。系统选择页会打开该系统的提交确认框，三处都使用本机加密保存的员工令牌。即使编辑器仍打开，也仅上传磁盘中已保存的配置，未保存的修改不会进入审核包。仍可导出审核包后在网站手动上传。优化已有公司系统时，从软件“公司系统库”选择已发布版本创建独立本机草稿；在草稿中修改、预览和测试后查看变更，再提交到原系统 ID 的下一版。正式受管包只读，本机草稿不要求该公司系统的密钥授权。包含用户分类器的已发布包暂不能自动派生草稿，界面会明确提示；不能丢弃算法后冒充完整更新。HTTP 接收仅表示待审核。
   已发布 ID 冲突时，提交界面显示当前版本并要求明确选择“作为该版本更新”；新系统须换 ID。内置 ID/传感器类型和已有待审 ID 被拒绝。管理员发布前再次核对更新基线；版本已变化的旧审核包须重新提交。同 ID 更新不能改变传感器身份、输出通道和矩阵尺寸；协议与线序差异由审核页展示。
4. 超级管理员在网站核对配置、文件与算法，选择“全部客户”或指定客户并发布。后续可将同一不可变版本推广给更多客户，或只为指定客户指回旧版；全部客户操作会清除客户级覆盖。发布后的系统出现在开密钥页的“公司发布系统”组，客户仍须持有包含该系统 ID 的密钥。紧急撤回会停用该版本，指向它的客户在下次同步后暂时看不到系统；需要继续使用时应显式回退，不会自动选旧版。
5. 客户在软件验证可能包含公司系统的密钥后自动拉取签名授权目录与包；仅含内置系统的密钥不发起公司系统同步。服务端同时核对密钥是否包含该系统 ID、客户是否在发布范围内、密钥是否有效。每 6 小时复查，系统列表“刷新”可立即重试。受管系统独立于客户本地系统目录，安装失败保留旧版并显示错误。授权目录最长有效 24 小时；过期或撤回后不能新连接，当前受管采集由后台检查停用并断开。

在线密钥和已登记的离线 RSA 激活码都可在联网时同步公司系统。离线码须在密钥网站关联有效客户，且授权范围须包含目标公司系统 ID；旧密钥只包含原有系统时，需要管理员按新范围重新签发。门户对只含内置系统的密钥不显示公司系统同步提示；可能包含公司系统的密钥同步失败时，在系统列表显示中性说明，不把它作为软件密钥整体失效。此处不等于断网安装；真正离线导入授权文件仍未实现。

首期在线交付不修改安装包代码。新增传感器 framing、新原生页面或新的渲染/算法运行时仍须更新宿主安装包。服务器私钥、数据库迁移和真实设备的协议/线序验收是上线前必须完成的部署步骤；本地合成测试不能替代真机检查。

下文保留最初的设计推演；实际路由、迁移和上线参数以当前流程及 `E:/key/docs/system-packages.md` 为准。

## 目标与用户流程

```text
员工用 Agent 创建并在真实设备上验收
  → 提交审核（不可变系统包 + 验收摘要）
  → 管理员在密钥网站预览、核对、批准
  → 发布为公司系统库的新版本，指定全部客户或具体客户
  → 客户软件用现有软件密钥查询授权目录、校验并安装系统包
  → 软件提示“新系统已就绪”，客户可直接进入
```

员工提交只是候选版本；管理员批准后才进入可下载目录。系统 ID 稳定，发布版本不可覆盖。员工在本机继续编辑不影响已发布版本；下一次修改须重新提交。管理员可以撤回一个发布版本或把客户固定在上一稳定版本。客户本地创建的同名系统不能被覆盖，冲突时停止安装并给出可处理的提示。

## 当前代码的可复用边界

| 现有能力 | 位置 | 实施含义 |
| --- | --- | --- |
| Manifest 系统与定义文件 | `backend/extension-host/workspace/displaySystemWorkspaceService.js` | 可读取 `manifest` 与逐传感器线序、点位、坐标、算法定义；不能把 Builder 的完整 `save()` 当作任意 v3 系统导入器，它会重新编译配置。 |
| 原生模板副本 | `backend/extension-host/workspace/builtinSystemTemplates.js` | 副本声明依赖软件内的 `sourceType` 原生页面与协议；发布包只能引用已随客户软件交付的来源。 |
| 用户分类算法 | `backend/agent-runtime/algorithm-lab/realtimeCatalog.js` | 实时包来自 `agent/algorithm-lab/installed/`，必须与所属系统、输入契约和源码摘要一同交付。 |
| Manifest 算法绑定 | `backend/extension-host/workspace/manifestAlgorithmBindings.js` | 绑定位于独立 sidecar；系统包若漏掉它，会出现系统有画面但没有已配置的分类图表。 |
| 客户与密钥 | `E:/key/drizzle/schema.ts`、`E:/key/server/agentSyncStore.ts` | 已有客户、软件密钥和按密钥验证客户身份的实现，可复用鉴权规则，不能复用聊天上传正文作系统包。 |
| 软件更新 | `app/update/autoUpdater.js`、`scripts/upload-release.js` | 目前只分发整个安装包。新增原生渲染代码仍走软件更新；仅配置与受支持算法可走独立系统包更新。 |

现有 `LicensePortal` 使用密钥解出的 `selectFlag`；`portalSystems.js` 对已安装 Manifest 的列表规则仅要求有有效授权范围。要做按客户发布，必须新增**服务端授权清单与后端运行校验**，不能只隐藏前端卡片。旧离线密钥不具备即时服务端变更能力，须配合有期限的签名授权清单或重新签发。

## 交付包契约

每次提交由桌面端按引用关系构建白名单包，不直接压缩整个 `userData`。包应包含：

- `package.json`：格式版本、稳定系统 ID、系统类型、显示名称、来源系统、所需最低软件版本、完整文件清单及每个文件的 SHA-256。发布时间和正式版本号由服务器批准时分配。
- Manifest 系统：`display-system.json`、所有引用的协议/线序/点位/坐标/算法文件，以及可选 Agent 渲染资源。
- 原生模板副本：`sourceType`、可编辑配置、所依赖的软件最低版本；不得把内置原生页面源码伪装成配置文件。
- 已绑定的用户分类算法：对应已保存版本、输入契约、报告摘要、源码摘要、算法与图表绑定。只有离线版本时标为不可实时启用，不声称已部署。
- 验收摘要：真实设备型号、原始帧点数、展示矩阵、映射点数、线序抽样核对、算法报告版本、测试软件版本，以及“已真机验收／仅合成测试”的明确状态。

包**不包含**采集数据库和原始记录、聊天和附件、客户/员工密钥、模型 API Key、设备码、任意本机路径。需要分享测试数据时另走经用户选择的独立附件流程。服务端重新计算哈希、审查依赖并给批准版本签名；客户端仅信任内置公钥签名和与包一致的哈希。包大小、文件数量、扩展名和解压后路径必须设上限，拒绝路径穿越、链接文件及未声明文件。

## 服务端模型与接口

在 `E:/key` 增加三组数据；现有客户、密钥和人员表继续作为身份来源：

1. `system_submissions`：提交 ID、作者、原系统 ID、源修订号、包哈希、对象存储键、状态（待审核/退回/通过）、验收摘要和审核意见。
2. `system_releases`：稳定系统 ID、不可变版本、内容哈希、签名、最低软件版本、发布状态、替代或回滚版本。`(system_id, version)` 唯一。
3. `system_entitlements`：系统 ID、授权对象（全部客户或指定客户）、启停、版本策略及变更审计。按客户关联其有效软件密钥；无客户归属的密钥需显式处理，不能猜归属。

接口建议分为三种权限，不共用一个上传凭证：

| 使用方 | 建议接口 | 必须校验 |
| --- | --- | --- |
| 员工客户端 | `POST /api/system-submissions`，上传包并提交 | 员工登录身份、包大小/格式、请求幂等、每个引用文件完整性；客户软件密钥不能授予提交权限。 |
| 管理网站 | `GET /api/admin/system-submissions`、`POST /:id/review`、`POST /:id/publish`、`PATCH /api/admin/system-entitlements` | 审核/发布仅管理员；审核意见、发布版本、客户范围都留审计记录。 |
| 客户软件 | `GET /api/client/system-catalog`、`GET /api/client/system-packages/:systemId/:version` | 使用现有软件密钥验证有效期、状态、客户归属和该系统权限；下载接口也要鉴权，不能只保护目录接口。 |

员工身份与客户授权分开：桌面端通过浏览器登录密钥网站，取得短时、仅可提交系统包的员工令牌；不把管理员口令或长期上传密钥写进安装包。首批若暂不接员工登录，可先用“导出待审核包 → 管理网站上传”，其包格式与后续直传完全相同。

**密钥不必因每增加一个系统而更换。** 密钥标识客户，服务端的 `system_entitlements` 决定新增系统是否可用，客户软件定期取得由服务器签名、有明确有效期的授权目录。老桌面客户端只读本地 `selectFlag`，因此首次上线必须发布一次支持授权同步的安装包；之后配置系统可以单独发布。离线客户通过带有效期的签名授权文件更新权限，离线状态下无法做到即时撤销，应在产品规则中明确。

## 桌面端安装与授权执行

1. Agent 成果卡片增加“提交审核”和状态入口。先读回磁盘真实配置并检查依赖，再生成包；提交结果显示“待审核”，不把 HTTP 接收当成发布成功。
2. 客户端在密钥验证后拉取授权目录；以系统 ID 和版本比较本机已安装的**受管系统目录**。受管目录与用户创建的 `display-systems/` 分离，避免自动更新覆盖客户本地编辑。客户需要修改时先“另存为独立副本”。
   当前 `createManifestAlgorithmBindings.load()` 只接收 `editable === true` 的用户 Manifest，`createRealtimeAlgorithmCatalog()` 也只扫描用户算法目录。安装器须增加受管系统的只读绑定加载和受管算法目录发现，不能只复制 sidecar/算法 JSON 后宣称已运行；原生模板副本同样需要受管发现入口。
3. 下载到临时目录，检查签名、哈希、文件清单、软件版本、系统配置/线序/算法契约及系统 ID 冲突。全部通过后原子切换受管版本、重载发现与实时绑定；失败自动保留上一版本，采集库不迁移、不删除。
4. 门户只显示授权系统，后端 `sensor.switch` 和实时启用路径复核授权。在线授权缓存必须有到期时间；到期或撤销后停止受管系统的新连接，并清楚提示“授权已变化”。现有运行中采集的处理策略需在实现前固定并测试，不能靠列表隐藏代替停止。
5. 安装成功后提示系统名称、版本和“进入系统”；安装失败保留可重试状态与具体原因。软件版本过低时引导现有安装包更新。

这里最容易遗漏的联动是：Manifest 的原始帧点数可与展示点数不同，发布/安装不能按展示矩阵重新推导协议点数；算法包的 `systemId`、输入阶段、矩阵点数和绑定 sidecar 必须与发布后的系统一致。

## 实施顺序与验收

1. **包与安装器**：在 `backend/extension-host` 建立只读打包器、同一契约的本机预检/安装器及受管目录；用 Manifest、原生副本、带分类算法的三种系统验证往返一致。先支持手工导出/导入，可独立检验包边界。
2. **管理服务**：在 `E:/key` 增加迁移、对象存储、员工提交、管理员审查/发布和客户权限接口；保存不可变版本与审计。客户包接口使用实际密钥状态与客户归属鉴权。
3. **端到端接入**：Agent 增加直接提交状态；管理网站增加待审、预览、发布和客户范围；桌面端增加目录同步、安装恢复、授权复核与成果提示。先灰度一个内部客户，再放开所有客户。
4. **离线交付**：复用同一签名包和签名授权目录，增加文件导入；不另造一套验证器。

验收必须覆盖：1024 原始点映射 529 展示点、线序和真实设备画面；系统/算法/图表/Agent 渲染资源完整安装；未授权密钥无法列出、下载或运行；失效/吊销、跨客户访问、离线授权过期；同名冲突、包篡改、路径穿越、下载中断、版本回滚和软件版本不足；已采集数据与客户本地系统在更新后保持原样。使用合成帧只能证明配置链路，不能代替真实设备验收。
