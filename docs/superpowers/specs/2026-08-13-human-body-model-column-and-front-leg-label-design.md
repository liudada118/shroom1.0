# 人体全身优化模型列方向与前腿数字标题修正设计

## 目标

根据实物与视角验证，修正人体全身优化指定右侧区域在 3D 热力图中的左右方向，同时修正前腿 2D 数字面板的标题命名。3D 专用方向不能影响 2D 数字矩阵。

## 已确认的现象与范围

- 正面视角屏幕右侧的前腿在 3D 热力图中左右反向。
- 背面视角屏幕右侧的后腿在 3D 热力图中左右反向。
- 右手臂和右肩在 3D 热力图中都左右反向。
- 上述左右翻转只作用于 3D 热力图，不作用于 2D 数字矩阵。
- 前腿 2D 数字面板只交换“左前腿 / 右前腿”标题文字，不交换两块数字矩阵的位置或数据。

## 模型空间对应关系

`sensor_canvas_positions.json` 的实际 X 坐标证明：

- 前视屏幕右侧是模型正 X，对应 `frontPantsRight`。
- 后视镜头位于模型背面，屏幕左右相对模型 X 反转，因此背视屏幕右侧是模型负 X，对应 `backPantsLeft`。
- 上一轮实物左右归属修正后，实物右手臂与右肩的数据部位键分别是 `rightArm`、`rightShoulder`，它们采样到点位档案的模型负 X 一侧。

因此，3D 需要列翻转的准确数据部位键为：

- `frontPantsRight`
- `backPantsLeft`
- `rightArm`
- `rightShoulder`

## 根因

当前 `humanBodyOrientation.js` 的 `getSourceGridPosition()` 已支持 `flipCol`，但方向配置尚未为以上四个部位启用该选项。另一方面，2D 数字面板直接调用同一矩阵方向函数；如果把列翻转继续放进无上下文的公共配置，2D 也会被错误翻转。

前腿 2D 标题则直接按内部键命名：`frontPantsLeft` 显示“左前腿”、`frontPantsRight` 显示“右前腿”。用户确认数字块的位置与内容正确，只需互换标题文案。

## 方案选择

采用带渲染通道的方向配置。方向定义仍集中在 `humanBodyOrientation.js`，但 3D 采样和 2D 数字矩阵分别读取自己的方向通道：

- 3D 通道负责模型采样的行、列方向。
- 2D 通道只保留已确认的数字矩阵方向，不继承本次 3D 专用列翻转。

不采用以下方案：

- 在 `HumanBodyOptimized.jsx` 中为四个部位分别写反转补丁：规则会再次分散，容易与公共方向重复。
- 修改 `humanBody.jsx` 原始索引矩阵：会影响旧版人体渲染和其它复用者。

## 详细设计

### 3D 模型采样

`getSourceGridPosition()` 明确读取模型通道方向：

| 数据部位 | 上下方向 | 左右方向 |
| --- | --- | --- |
| `frontPantsRight` | 保持 | 翻转 |
| `backPantsLeft` | 翻转 | 翻转 |
| `backPantsRight` | 翻转 | 保持 |
| `rightArm` | 保持 | 翻转 |
| `rightShoulder` | 保持 | 翻转 |
| `back` | 翻转 | 保持 |

其它区域保持现有 3D 方向。

### 2D 数字矩阵

2D 矩阵不应用本次四个部位的 `flipCol`：

- `frontPantsRight` 保持原始数字列方向。
- `backPantsLeft` 只执行已有上下翻转，不执行左右翻转。
- `rightArm`、`rightShoulder` 保持原始行列方向。
- 后背、左右后腿的既有 2D 上下规则保持不变。
- 前胸、后背已有的数字面板横向排版补偿保持不变。

为避免共享配置误用，矩阵方向函数需显式表达 2D 通道，而不是隐式复用全部 3D 规则。

### 前腿标题

数字面板中的两个前腿块保持现有顺序和数据：

| 数字块内部键 | 新标题 |
| --- | --- |
| `frontPantsLeft` | 右前腿 |
| `frontPantsRight` | 左前腿 |

后腿标题、手臂标题和其它区域标题不变。

## 测试与验收

- 用源矩阵首列/末列唯一值验证四个指定部位的 3D 首尾列互换。
- 验证 `backPantsLeft` 在 3D 同时执行上下和左右翻转。
- 验证 `backPantsRight` 仍只上下翻转。
- 验证四个指定部位的 2D 数字列方向不因 3D 配置改变。
- 验证前腿两个数字块顺序与数据不变，标题分别显示“右前腿”“左前腿”。
- 运行人体方向专项 Vitest 和前端生产构建。
