# 人体全身优化左右区域与方向修正设计

## 目标

修正“人体全身优化”中左右手臂、左右肩的整块数据归属，并统一后背、左右后腿的上下显示方向。3D 热力图与视角切换时的 2D 数字面板必须表达同一套身体区域和方向。

## 已确认的实物规律

- 按压真实右手臂时，当前热力落在模型左手臂；真实左手臂同样落在模型右手臂。
- 左右肩也存在相同的整块互换。
- 左右手臂完成整块互换后，区域内部保持原始行列方向，不再执行额外的上下或左右翻转。
- 后背需要上下翻转。
- 左后腿和右后腿都需要上下翻转。

## 根因

`sensor_canvas_positions.json` 以模型空间正负 X 标记左右区域，而当前运行数据的 `rightArm`、`leftArm`、`rightShoulder`、`leftShoulder` 使用的是实物人体左右语义。渲染层直接按同名区域绑定，导致两套左右定义相反。

方向处理还分散在两处：公共方向模块为右手臂设置了 `flipRow`，2D 数字面板又为手臂设置横向翻转、为后腿设置纵向翻转。这会让 3D 与 2D 不一致，并在新增规则时产生双重翻转。

## 方案选择

采用渲染层归属修正：保留原始 1024 路帧、部位索引矩阵和 v7 点位档案不变，在点位区域解析到数据部位时交换左右手臂和左右肩。

不采用以下方案：

- 重写点位 JSON：会破坏从源项目迁移的 v7 点位档案及其可追溯性。
- 交换 `humanBody.jsx` 的全局索引矩阵：会影响旧版人体渲染及其他复用者。

## 详细设计

### 区域归属

3D 物理点位仍使用 JSON 中的坐标和区域名称，但采样数据部位按以下映射读取：

| 模型点位区域 | 读取的数据部位 |
| --- | --- |
| 左手臂 | `rightArm` |
| 右手臂 | `leftArm` |
| 左肩 | `rightShoulder` |
| 右肩 | `leftShoulder` |

前胸、后背和前后腿保持现有区域归属。

视角按钮中的“左臂”“右臂”按人体自身左右语义定位到交换后的模型空间一侧；对应 2D 面板继续展示同名实物数据部位。

### 区域内部方向

公共方向配置支持行与列两个独立维度，并同时服务 3D 双线性采样和 2D 数字矩阵：

| 数据部位 | 行方向 | 列方向 |
| --- | --- | --- |
| `back` | 上下翻转 | 保持 |
| `backPantsLeft` | 上下翻转 | 保持 |
| `backPantsRight` | 上下翻转 | 保持 |
| `leftArm` / `rightArm` | 保持 | 保持 |
| `leftShoulder` / `rightShoulder` | 保持 | 保持 |

2D 数字面板移除手臂的额外横向翻转和后腿的独立纵向补偿，避免公共方向规则与面板私有规则叠加。其它已存在且未被本次实物反馈否定的 2D 显示规则保持不变。

## 数据边界

本次只改变可视化读取关系，不改变：

- 原始 1024 路实时帧及其索引值；
- 采集回放和 CSV 下载内容；
- 左侧压力统计的原始矩阵来源；
- `sensor_canvas_positions.json` 的 1120 个物理坐标、行列及线网连接；
- 旧版人体展示系统的部位索引矩阵。

## 测试与验收

- 用不同的四角值验证左右手臂、左右肩的模型区域读取到对侧命名的数据部位。
- 验证左右手臂和肩内部行列不翻转。
- 验证后背、左后腿、右后腿首行读取原始矩阵末行，列方向保持。
- 验证前胸及前腿等无关部位不受影响。
- 验证 3D 采样与 2D 数字矩阵使用同一方向配置，每项转换只发生一次。
- 运行相关 Vitest 测试和前端生产构建。
