# 日文生命体征语音与状态翻译修正设计

## 目标

修正日文界面下生命体征告警可能使用中文系统声音的问题，并按用户给定术语把“已坐起”和“坠床风险”的日文界面文本、告警语音文本统一为“端座位”。日文语音包的安装和系统配置不在本次代码范围内。

## 当前问题与根因

`Home.jsx` 已把告警文本交给 i18next，并把 utterance 语言设为 `ja-JP`；但当前 voice 筛选使用完整字符串 `voice.lang.startsWith(utter.lang)`。当系统返回 `ja`、`ja_JP` 或语音列表尚未加载时，代码找不到日文 voice，随后不设置 `utter.voice`，系统可能用默认中文 voice 播放。

日文目录中状态还存在两套键：Aside 使用 `fallBed` / `sitUp`，语音告警使用 `home.alerts.fallRisk` / `home.alerts.satUp`。只修改其中一套会造成界面与语音不一致。

## 设计

新增一个无 UI 依赖的日文语音选择模块：

- 语言标签统一转为小写并把 `_` 转为 `-`，按基础语言匹配，因此 `ja`、`ja-JP`、`ja_JP` 都归入日文 voice。
- 日文模式只允许选择基础语言为 `ja` 的 voice；不得选择中文 voice，也不得交给系统默认中文 voice 播放。
- 首次读取语音列表为空或没有日文 voice 时，监听一次 `voiceschanged` 后重试；重试仍无日文 voice 时跳过播报并写入警告日志。
- 中文和英文继续选择各自语言 voice；现有女性声音关键词只用于同语言 voice 内的优先排序。
- `Home.jsx` 只负责传入已经由 i18next 翻译的文本和当前语言，语音选择细节由新模块负责。

日文目录同步修改四个键：

- `fallBed` → `端座位`
- `sitUp` → `端座位`
- `home.alerts.fallRisk` → `端座位`
- `home.alerts.satUp` → `端座位`

中文、英文文本和协议状态码保持不变。

## 测试

- 单元测试覆盖 `ja` / `ja-JP` / `ja_JP` 匹配日文 voice。
- 单元测试保证日文模式不会选择中文 voice。
- 单元测试覆盖语音列表延迟加载后重试并播报。
- 单元测试覆盖没有日文 voice 时不调用 `speechSynthesis.speak()`。
- 国际化测试同时断言四个日文键均为“端座位”，中文和英文值不变。
- 运行前端专项测试、生产构建和 `git diff --check`。

## 非目标

- 不自动安装或下载 Windows/macOS 日文语音包。
- 不修改生命体征状态码、触发条件或播报频率。
- 不修改其它语言翻译、其它告警文案或语速音量。
