# 256 点单帧矩阵（16×16）

**JSON 预设**：[`matrix-256.json`](matrix-256.json) ✅ 系统可直接加载

最简单的一种：一帧就是一整张 16×16 矩阵，没有拼包、没有校验、没有额外字段。
`eye` / `daliegu` / `smallSample` / `footVideo` 这类小矩阵传感器走它。

## 帧结构

```
┌──────────────┬──────────────────────────────────┐
│ AA 55 03 99  │ 256 × uint8                      │
│ 分隔符 4B    │ 压力点，0~255                     │
└──────────────┴──────────────────────────────────┘
```

| 项 | 值 |
| :--- | :--- |
| 分隔符 | `AA 55 03 99` |
| 分帧方式 | 按分隔符切分，分隔符不保留 |
| 有效载荷 | 256 字节 |
| 数据类型 | `uint8` |
| 点数 | 256（16×16） |
| 默认波特率 | 921600（预设值，见下） |
| 校验 | 无。判定条件只有帧长 `=== 256` |

## 波特率没有唯一正确值

判定这个协议的代码**只看帧长**，不看传感器类型：

```js
if (buffer.length !== 256) return null;
```

所以「256 字节帧」是一族传感器共用的形状，各自波特率不同：
`eye` / `daliegu` / `smallSample` / `footVideo` 是 921600，没有显式声明波特率的类型走默认 1000000。
预设填的是 921600（覆盖了已知的大多数），**接上新硬件时优先怀疑这个字段**。

## 和手套协议的关系

手套类协议的压力段也是 256 点，但它们的**帧不是 256 字节**（274 / 262 / 130+146），
压力之外还带 IMU 或姿态字节。别把手套硬件配成这个预设 —— 长度不匹配，一帧都收不到。
对应文档：[整包 274](hand-glove-full-packet-274.md)、[262 帧](glove-262.md)、[双包](hand-glove-double.md)。

## 排错

| 现象 | 一般原因 |
| :--- | :--- |
| 一帧都收不到 | 波特率不对（先试 921600，再试 1000000） |
| 帧长是 274 / 262 / 130 / 146 | 硬件是手套，选错协议了 |
| 有帧但矩阵方向不对 | 线序问题，不是协议问题 |
