# 历史数据 CSV 导出

> 最后更新：2026-08-29

把 SQLite 里的历史帧导成 CSV 落盘，全程向前端上报进度。只做导出，不查数据库结构、不管回放。

## 本目录文件

| 文件 | 作用 | 边界 |
| --- | --- | --- |
| `csvDownloadService.js` | 导出全流程：校验目标目录可写、分页读历史数据、构造 CSV 记录、写 UTF-8 BOM 文件，并通过系统事件上报进度 / 成功文件列表 / 失败原因。导出 `createCsvDownloadService`、`validateWritableDirectory`、`writeCsvFile` | 依赖注入 `fs` / `path` / 数据读取函数，自己不 require 它们，所以能不落盘测试。CSV 序列化用 `csv-writer` 的 `createObjectCsvStringifier` |

## 两件容易踩的事

**UTF-8 BOM 是必须的，不是可选的。** `CSV_UTF8_BOM = '﻿'` 写在文件开头，因为客户几乎都用 Excel 打开。少了这三个字节，中文表头在 Excel 里就是乱码——而这属于典型的静默失败：文件能打开、数据是全的、只是没人看得懂。

**分页读取不是为了省内存，是为了能上报进度。** 一次性 `SELECT *` 也跑得动，但导出过程中前端拿不到任何反馈，几万帧的导出看起来就像卡死了。

## 边界

- 目录校验失败时返回 `{ ok: false, error }` 而不是抛错，让调用方决定怎么提示用户。
- 不负责决定导出哪些字段、时间戳怎么格式化——那些由调用方传进来的记录构造函数决定。
